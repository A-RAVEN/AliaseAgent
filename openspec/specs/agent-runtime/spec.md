# agent-runtime Specification

## Purpose

规定 Agent 运行对象的边界：每个实例持有自己的上下文句柄、创建时解析的不可变生效配置、独立消息历史、模型—工具循环、取消与计量状态，以及统一的创建、注册与销毁路径。界面只负责展示与会话交互，不再直接持有模型执行逻辑；模板与运行实例是两类对象，修改模板只影响之后创建或恢复的实例。当前 Session 的模板切换必须替换运行实例，同时保留同一会话的上下文、消息历史与工具输出溢出文件。

## Requirements

### Requirement: 每个 Agent 使用不可变的实例生效配置

系统 SHALL 在创建 Agent 时由模板解析出不可变的实例生效配置，至少包含 provider 引用、模型、推理模式与强度、系统提示词、工具清单、上下文窗口、压缩参数、图片输入模态、命令超时与不可压缩要求。合法推理强度 SHALL 解析为 `adaptive`，缺失或非法值 SHALL 解析为 `disabled`。每次创建与保存都 SHALL 校验 `maxContextTokens` 为正整数；配置缺失、为零或为负时 SHALL 显示模板名并拒绝创建，不得按 0 继续、静默关闭压缩或整段发送，压缩阈值 SHALL 继续由窗口乘百分比推导。

provider 密钥 SHALL 仅作为创建时的私有执行依赖使用，SHALL NOT 出现在实例生效配置的可序列化快照、模板菜单或日志中；真实创建与发送路径的日志断言 SHALL 能检出密钥泄漏。Agent 运行中 SHALL 使用创建时的配置，不得因其它模板或实例随后修改而热更新。

#### Scenario: 非法窗口不得静默整段发送

- **WHEN** 一个非 `general` 模板的 `maxContextTokens` 缺失、为零或为负，使用该模板创建或恢复 Agent
- **THEN** 创建失败并显示该模板名，不得按 0 继续、关闭压缩或发送全文

#### Scenario: 两个实例使用不同配置

- **WHEN** 两个 Agent 分别由不同模板创建，模板的模型与推理强度不同
- **THEN** 两个实例各自发送的模型请求使用创建时解析的模型与推理配置，互不覆盖

#### Scenario: 创建后修改模板不热更新

- **WHEN** 一个 Agent 已创建，随后其来源模板的模型或推理强度被修改并保存
- **THEN** 该 Agent 后续执行仍使用创建时的生效配置，之后新建或恢复的实例才使用修改后的配置

#### Scenario: 密钥不进入快照

- **WHEN** 一个 Agent 已解析 provider 并生成实例配置或上下文快照
- **THEN** 快照、模板菜单和日志不包含 provider 的 `api_key`

### Requirement: Agent 独立拥有执行状态与消息历史

每个 Agent SHALL 持有自己的上下文句柄、消息历史、模型—工具循环、取消与请求状态、计量和销毁状态。模型、工具与摘要调用产生的数据库写入 SHALL 归属于该 Agent 的会话，不得读取界面当前会话 id 顶替。界面 SHALL 通过 Agent 的事件或回调展示状态，不再直接拥有模型执行逻辑。

#### Scenario: 两个实例交替执行

- **WHEN** 两个 Agent 分别属于不同会话并交替执行模型、工具和摘要调用
- **THEN** 每个请求、工具结果、摘要和消息写入仍归属于各自会话，不共用可变消息列表或请求队列

#### Scenario: 界面切换不改变执行归属

- **WHEN** 一个 Agent 正在执行，界面随后选中另一个会话
- **THEN** 原 Agent 的请求、取消、回调与数据库写入仍使用原句柄，不读取新的当前会话 id

### Requirement: 统一创建、注册与销毁 Agent

系统 SHALL 提供统一的 Agent 工厂与运行实例注册表。工厂 SHALL 在创建时确保对应上下文存在并初始化工作区，注册表 SHALL 按句柄管理运行实例。销毁 SHALL 先停止新调用，等待本 Agent 的整轮 Future（模型循环、工具、消息与工具记录写库、后台压缩写库）结束，再通过既有 `disposeContext` 排空桥内队列与 C++ 在途调用，最后释放实例；不得把 `disposeContext` 单独当成整轮写库已经排空。模板注册表与运行实例注册表 SHALL 是不同对象。

#### Scenario: 创建并恢复实例

- **WHEN** 通过工厂新建或恢复一个会话的 Agent
- **THEN** 工厂确保对应上下文存在，实例按该会话句柄登记，且只有 `created:true` 时设置缺省工作区

#### Scenario: 销毁实例

- **WHEN** 销毁一个仍有模型、工具或后台摘要操作的 Agent
- **THEN** 整轮 Future 与后台压缩写库先结束，随后才调用 `disposeContext` 并释放实例；数据库删除或资源释放不得早于最后一次写库，其它实例的上下文、请求和消息历史不受影响

### Requirement: Agent 按生效配置过滤实际工具与请求参数

系统 SHALL 以 `ToolCatalog` 作为工具定义的唯一只读目录，Agent SHALL 按实例生效配置过滤该目录中的工具，只有配置允许的工具才能进入模型请求。配置或编辑结果含目录中不存在的工具名时 SHALL 显式报错并列出名字，不得静默丢弃。模型、`thinkingMode`、`thinkingEffort` 和系统提示词 SHALL 由同一份实例生效配置传入既有 `sendMessage` 路径，不得在发送前从其它全局配置重新读取。

#### Scenario: 未允许的工具不发送

- **WHEN** 模板允许文件读取工具但不允许命令工具，使用该模板的 Agent 发起模型请求
- **THEN** 请求的工具定义包含文件读取工具且不包含命令工具

#### Scenario: 未知工具名必须可见

- **WHEN** 既有配置或模板编辑结果包含 `ToolCatalog` 中不存在的工具名
- **THEN** 创建或保存失败并列出该工具名，不得只从请求中静默移除后继续

#### Scenario: 请求参数来自本实例

- **WHEN** 一个 Agent 使用指定模型、推理强度和系统提示词发起请求
- **THEN** 实际 `sendMessage` 参数与该 Agent 的生效配置一致，不使用 `general` 或其它实例的值

### Requirement: Session 切换模板必须替换运行实例

当前 Session SHALL 提供 Agent 模板选择入口。切换 SHALL 先通过与创建路径一致的候选预检，再在界面提交与数据发送两层阻止该 Session 的新发送和重复切换，等待旧实例整轮操作与后台压缩写库自然结束并退役旧 Agent 对象，持久化新的 `agent_type`，最后用该 Session 的界面回调创建并注册新实例。界面选择、数据库值与实际请求 SHALL 使用同一个模板名，不得只改显示或数据库而继续复用旧实例。

切换 SHALL 保留该 Session 的上下文句柄、工作区、消息、工具记录、摘要数据与工具输出溢出文件，其它 Session 的运行实例不受影响。退役旧 Agent 对象 SHALL NOT 调用 `disposeContext`；新实例 SHALL 沿用同一句柄，使历史 `read_spill` 引用可读且后续输出不覆盖旧文件。只有删除 Session 或关闭应用等真正销毁上下文的路径才删除这些资源。

旧实例的上下文占用快照 SHALL 在切换时清除，直到新实例完成下一次真实请求。普通创建或恢复路径发现已注册实例的模板名与 Session 不一致、或实例正在退役时 SHALL 显式失败，不得静默复用。没有当前会话时只禁用模板选择控件，既有“直接发送则自动创建 `general` Session”行为 SHALL 保持不变。

#### Scenario: 切换后真实请求使用新模板

- **WHEN** 用户把同一 Session 从 `general` 切换到另一合法模板并发送消息
- **THEN** 旧 Agent 对象已退役，新实例恢复同一消息历史，实际请求的模型、推理配置、系统提示词和工具来自新模板，数据库中的 `agent_type` 也已更新，新消息通过界面回调出现在聊天区

#### Scenario: 在途轮次切换先排空

- **WHEN** 一个 Session 正在执行模型、工具或后台压缩写库，用户切换 Agent 模板
- **THEN** 该 Session 不接受新的发送或重复切换，不调用 `cancelRequest` 中断当前轮，旧实例的整轮 Future 和写库自然结束后才退役旧 Agent 对象并创建新实例

#### Scenario: 回车与直接发送不能在切换中穿透

- **WHEN** 切换正在进行，用户按回车、点击发送或调用数据发送入口
- **THEN** 三条路径都被切换状态拒绝，不得在旧实例退役前另建 Agent 或向已退役实例发送

#### Scenario: 切换与删除互斥

- **WHEN** 同一 Session 的切换与删除相继发生
- **THEN** 删除进行中切换被拒绝；切换进行中删除等待切换结束后重新读取 Session，不会提前删行或为已删除 Session 创建新实例

#### Scenario: 切换保留工作区与历史溢出引用

- **WHEN** 旧实例已经产生工作区状态和可供 `read_spill` 读取的工具输出文件，用户切换模板
- **THEN** 退役路径不调用 `disposeContext`，新实例沿用同一句柄与工作区，旧引用仍可读，新写入的溢出文件不覆盖旧引用

#### Scenario: 切换不影响其它 Session

- **WHEN** 两个 Session 各有运行实例，用户只切换其中一个 Session 的模板
- **THEN** 另一个 Session 的实例、配置、消息历史与在途请求保持不变

#### Scenario: 切换后清除旧实例占用快照

- **WHEN** 旧实例已有 `ContextSnapshot`，用户完成 Agent 模板切换
- **THEN** 界面不再把旧实例的窗口与占用环当作新实例状态，直到新实例产生下一次真实请求快照

#### Scenario: 无当前会话时直接发送保持既有行为

- **WHEN** 应用没有当前 Session，用户直接输入并发送
- **THEN** 选择控件不可用，但发送仍自动创建默认 `general` Session 并完成本轮，不因新增切换守卫而被拒绝

#### Scenario: 普通恢复发现实例模板不一致

- **WHEN** `AgentFactory.ensure` 发现注册表中的实例模板名与 Session 当前保存的 `agent_type` 不同，或实例正在退役
- **THEN** 工厂显式报出实际状态与期望模板名，不得直接返回旧实例

#### Scenario: 切换中途失败不伪装成功

- **WHEN** 候选预检之后的退役、持久化或新实例创建失败
- **THEN** 界面显示失败阶段与候选模板名，并重新读取数据库使选择框与实际保存值一致；若新实例未创建成功，不得显示为已正常运行或静默退回 `general`

### Requirement: 同一轮内连续的只读工具调用并发执行

Agent 的模型—工具循环 SHALL 把同一轮内**连续的只读工具调用**归入同一个并发组同时执行；只读集合为 `read_file`、`list_dir`、`glob_file`、`grep_file`、`read_spill`、`read_image`、`get_current_time`、`web_search`、`web_fetch`。写类与有状态工具（`write_file`、`edit_file`、`run_command`、`browser_navigate`、`browser_click`、`browser_type`、`browser_snapshot`、`spawn_subagent`）以及**任何不在只读集合里的工具名** SHALL 逐个单独执行（默认串行，新工具未归类时落在安全侧）。组与组之间、组内成员与相邻写类调用之间的原始先后顺序 SHALL NOT 交换：前一组的最后一个结果产生后，才开始执行下一组。并发组的默认大小 SHALL 等于该连续只读段的成员数、不设硬编码上限；配置项 `tool.parallel_max`（默认 0 = 不设上限；正整数 = 单组一次最多同时启动的成员数）生效时，超出部分 SHALL 按原顺序在其后的子段中执行，交付顺序 SHALL NOT 因此改变。

#### Scenario: 连续三个只读调用重叠执行

- **WHEN** 模型在一轮里连续发出 3 个只读工具调用（如用户判据点名的 3 个 `read_file`），且每个调用在实际执行层耗时明显大于零
- **THEN** 三个调用的执行时间窗重叠，该段的总等待量级等于最慢一个调用的耗时，而不是三个耗时之和

#### Scenario: 单个只读调用维持现有执行路径

- **WHEN** 模型一轮里只发出一个只读工具调用（后续紧跟写类调用或本轮到此为止）
- **THEN** 该调用走与并行化之前相同的执行方式与顺序，行为与时序无回归

#### Scenario: 写类调用前后的只读不被提前

- **WHEN** 模型一轮里依次发出 `grep_file`、`write_file`、`read_file`
- **THEN** `read_file` 的执行在 `write_file` 的结果产生之后才开始（它读到的是写入后的状态），`grep_file` 不与 `write_file` 同时执行

#### Scenario: 连续写类调用保持逐个执行

- **WHEN** 模型一轮里连续发出 2 个 `write_file` 调用
- **THEN** 两个调用按发出顺序逐个执行（各走逐个段），执行时间窗不重叠

#### Scenario: 未知工具名默认串行

- **WHEN** 一轮里出现一个不在只读集合里的工具调用（包括未来加入工具目录的新工具名）
- **THEN** 它单独成段逐个执行，且其后紧邻的只读调用要等它结果产生后才开始

#### Scenario: 配置了并发上限时段按上限拆分

- **WHEN** `tool.parallel_max` 配置为 2，模型一轮里连续发出 4 个只读调用
- **THEN** 前 2 个先并发执行，其结果全部产生后剩下 2 个才并发执行，交付给模型/界面/落库的顺序仍是 4 个调用的发出顺序

### Requirement: 并发结果按模型发出顺序交付

并发组内各成员的**执行**可以任意先后完成，但**交付** SHALL 严格按模型发出 `tool_use` 的原始顺序：写回模型请求体的 `tool_result` 块顺序、界面工具结果卡片的回调顺序、`toolCallsJson` 落库的富化顺序三者 SHALL 与串行执行时逐位一致。组内单个成员失败或超时 SHALL NOT 阻断同组其它成员：失败者按既有错误形态（`ok:false` 与错误文本）交付，成功者照常返回，不存在整组一起失败或结果缺失。失败者的错误文本 SHALL 包含工具名与实际失败原因（异常原文或超时说明），SHALL NOT 用不含原因的通用文案顶替。

#### Scenario: 完成顺序与发出顺序相反时请求体不变形

- **WHEN** 并发组内第 1 个调用比第 3 个调用更晚结束
- **THEN** 发给模型的 `tool_result` 块仍按发出顺序排列（第 1 个的结果在前），界面卡片与落库顺序同样按发出顺序

#### Scenario: 组内一个成员失败不影响其它成员

- **WHEN** 并发组内某个 `web_fetch` 超时返回错误，同组的 `read_file` 与 `grep_file` 正常返回
- **THEN** 三个结果都按发出顺序交付：失败者携带含工具名与超时原因的错误文本，成功者携带各自内容，下一轮模型请求照常组装

### Requirement: 取消对并发组的语义

并发组启动前发现本轮已被取消时 SHALL NOT 启动组内任何调用；组执行途中收到取消时，系统 SHALL 等待已启动的成员自然结束（不泄漏后台执行单元），随后丢弃全部结果，不再向模型追加这一轮的 `tool_result`，并按既有取消路径结束本轮。被丢弃的调用在模型发出 `tool_use` 时已经以"执行中"卡片出现在界面：取消收尾 SHALL 把这些卡片置为终态并写明"本轮被取消，该工具结果未取回"，同一说明 SHALL 随 `toolCallsJson` 落库；后续历史重放为这些 `tool_use` 合成的 `tool_result` SHALL 携带该取消说明，SHALL NOT 是空文本（让模型能区分"工具返回空"与"因取消没有结果"）。

#### Scenario: 取消先于组启动

- **WHEN** 用户在并发组启动前取消了本轮
- **THEN** 组内没有任何工具被实际执行，本轮按取消结果结束

#### Scenario: 取消发生在组执行途中

- **WHEN** 并发组已在执行（界面上各成员卡片显示"执行中"），用户此时取消
- **THEN** 已启动的调用各自自然结束且结果被丢弃、不进入模型请求；这些卡片不再是"执行中"，转为带"因取消未取回结果"说明的终态；后续轮次不再发出

#### Scenario: 取消后重放历史带取消标记

- **WHEN** 上一轮因取消丢弃了并发组结果，用户随后在同一会话继续发消息触发历史重放
- **THEN** 发给模型的该轮 `tool_result` 内容包含"因取消未取回结果"的说明文本，而非空字符串

### Requirement: 子 Agent 复用同一并发执行规则

`spawn_subagent` 创建的子 Agent 运行 SHALL 与主 Agent 使用同一套分组、按序交付与取消规则（子运行本就复用同一循环实现），规范以本条钉住这一事实，防止未来出现"父并行、子串行"的分叉实现。

#### Scenario: 子 Agent 轮内的连续只读同样并发

- **WHEN** 子 Agent 在一轮里连续发出多个只读工具调用
- **THEN** 这些调用按同一分组规则并发执行，结果按发出顺序进入子 Agent 的模型请求
