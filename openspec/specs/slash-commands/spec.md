# slash-commands Specification

## Purpose

规定用户消息以 `/技能名` 显式触发技能加载时，进入模型请求的装配面展开规则：一条 user 消息的斜杠首段逐字等于当轮生效技能名时，发给模型的文本被替换为固定的 `load_skill` 加载指示模板；对话视图气泡、消息落库与会话标题始终保留用户手打原文，未命中一律原样透传、不报错。

## Requirements

### Requirement: 用户消息的斜杠技能展开

用户消息 SHALL 在进入模型请求的装配阶段接受斜杠展开判定：消息文本非空且第一个字符为 `/`，且斜杠之后到首个空白字符（空白字符的集合钉死为 U+0020 空格、U+0009 制表、U+000A 换行；**全角空格 U+3000 不算空白**）或文本末尾为止的首段**逐字等于当轮生效技能名**（`SkillCatalogService` 当轮生效集合；命中口径为设计决定：逐字匹配、大小写不一致即不命中——技能名受 `skill_frontmatter.dart` 的 `validateSkillMd`/`_kSkillNamePattern` 约束只含小写字母/数字/连字符，见 `Docs/AgentSkillsDoc.md` 第一节字段表）时，发给模型的该条 user 消息文本 SHALL 被替换为固定模板。模板形态为**固定前缀句 + 两个换行 + 余下正文**（余下正文可以为空），前缀句（精确措辞以实现常量与用例断言为准）：`已按斜杠命令展开技能 "<技能名>"：请先调用 load_skill(skill: "<技能名>") 读取该技能说明并严格遵循其中的指令，然后处理下面的请求：`。

判定 SHALL 对**进入本次请求的每一条** user 消息独立执行（不止当轮最后一条），且是**纯函数、幂等**的：同一文本在同一生效集合下任何一轮的结果相同。被压缩折叠进摘要的 user 消息不再接受展开、也不再携带加载指示（摘要按原文生成），属压缩能力的既定损失，首版不补偿。展开判定只作用于 `Message` 行 `role == 'user'` 的 `content` 文本；assistant 消息不参与判定；API 请求装配时注入的 `tool_result` 内容块（装在 API 层 `role=user` 的消息里，不是 `Message` 行）也不参与判定、SHALL NOT 被改写。

对话视图的聊天气泡与消息落库内容 SHALL 始终是用户手打原文；会话标题仍由原文文本生成，沿用既有规则——首条消息取前 30 字符、超出加 `...`（出处：`openspec/specs/session-persistence/spec.md` 的 Scenario「Auto-title from first user message」），不含展开模板。既有「真实上下文」视图按其既有规范显示实际发出的内容（快照 = 实际发送的 apiMessages），因此其中该条 user 消息会显示展开后的模板全文——如实披露，不加遮掩。消息文本为空串（例如只有图片附件的历史消息）SHALL 原样透传。

未命中（`/` 单独出现、首段不是任何当轮生效技能名、大小写不一致、消息不以 `/` 开头、首段与技能名之间不是空白分界如 `/edge-skill正文`、消息文本为空串）SHALL 原样透传，不报错、不产生任何界面提示。模板是固定代码常量，SHALL NOT 新增配置项；改措辞需同步实现常量注释、整段用例断言与用户文档三处，改漏任何一处相关用例必须红。

#### Scenario: 命中展开，对话视图零痕迹
- **WHEN** 生效技能集合含 `edge-skill`，用户发送 `/edge-skill 把这段文字按技能要求处理`
- **THEN** 模型该轮收到的 user 文本逐字等于 `已按斜杠命令展开技能 "edge-skill"：请先调用 load_skill(skill: "edge-skill") 读取该技能说明并严格遵循其中的指令，然后处理下面的请求：` + 两个换行 + `把这段文字按技能要求处理`；对话视图气泡与落库中的 user 消息逐字是用户手打的原文，标题按既有 30 字符规则由原文生成

#### Scenario: 未命中原样透传
- **WHEN** 用户发送 `/unknown 你好`（`unknown` 不是当轮生效技能名）、`/你好`、以空格开头的 `/edge-skill`、`/edge-skill正文`（无空白分界）或只发 `/`
- **THEN** 模型收到的 user 文本与用户手打内容逐字一致，无任何报错或提示

#### Scenario: 空正文也展开
- **WHEN** 用户只发送 `/edge-skill`（无任何余下正文）
- **THEN** 模型收到的 user 文本是完整的加载指示（技能名正确、文本止于前缀句后的两个换行），不因为没有正文而失败或透传

#### Scenario: 历史消息逐条展开（技能未删）
- **WHEN** 生效集合含 `edge-skill`，第一轮发送 `/edge-skill 干活`，第二轮又发送一条普通消息触发重新装配
- **THEN** 第二轮发给模型的历史里第一轮那条仍是展开版（含 load_skill 指示与技能名），第二轮新消息逐字为原文、不被误展开

#### Scenario: 历史消息按当轮集合重新判定
- **WHEN** 第一轮发送 `/edge-skill 干活` 后轮间用户删掉了 `edge-skill` 技能，又发送一条普通消息触发第二轮装配，且第一轮那条消息未被压缩折叠进摘要
- **THEN** 第二轮发给模型的历史里那条 `/edge-skill 干活` 不再展开、原样出现（判定以当轮生效集合为准）

### Requirement: 技能名补全交互

输入框文本以 `/` 开头、光标位于首段之内（首段 = 斜杠之后到首个 U+0020/U+0009/U+000A 为止；光标条件钉死为 `selection.isValid && selection.isCollapsed && 1 <= selection.baseOffset <= 首段末`，越界或非法 ⇒ 面板不显示）、输入框持有焦点、**且首段之后没有任何文本**时，应用 SHALL 在输入框上方显示候选面板：内容为**最近一次扫描**的生效技能名（`SkillCatalogService` 生效集合，读取即 `scan()` 快照，不触发扫描；按 names 输入顺序全量——数据源本身已按名字字典序），每次打开与每次击键重筛时现读，不缓存、不监听。查询串（首段去掉开头 `/`）对技能名的匹配 SHALL 为不区分大小写的按序子序列匹配（按序不必相邻，如 `/egk` 命中 `edge-skill`），前缀命中 SHALL 排在子序列命中之前、其余命中按首次命中位置排序（借鉴 DSH fuzzy-label 的排序骨架，不移植对齐分）；空查询 SHALL 按 names 输入顺序全量列出；无命中 SHALL 显示一行"无匹配技能"提示（中性信息色），面板 SHALL NOT 因此消失。

面板可见**且存在高亮行**时，输入框 SHALL 拦截以下按键（先于输入行既有的 Enter→发送分支）：`Tab` 与回车接受当前高亮行——把首段替换为 `/完整技能名␣`（尾部一个空格，光标落在其后，**首段之后的文本原样保留**），面板随即按关闭条件消失；`↑`/`↓` SHALL 移动高亮；`Esc` 与 `Shift+Tab` SHALL 关闭面板且不改写文本；鼠标点击候选行 SHALL 等同接受。**零候选（无匹配或空目录）时按键一律不被拦截**：Enter 仍发送、Tab 仍走默认焦点遍历——面板只是提示层，不吞键。接受补全 SHALL NOT 触发发送——发送仍由用户显式进行（面板可见且有高亮行时回车是"接受补全"不是发送；接受后或 Esc 关闭后再按回车才发送），装配面展开语义沿用「用户消息的斜杠技能展开」条文，接受补全前后的展开行为逐字节一致。

关闭条件（任一成立即关）：光标离开首段（打出第一个空白）、文本首字符不再是 `/`、输入框失焦、Esc/Shift+Tab、首段后出现了文本。空生效技能集合时键入 `/` SHALL 显示一行空态提示（精确串：「装一个技能后这里会自动出现候选（详见 skills.md）」），不出现任何候选行、不报错。接受补全 SHALL NOT 触发发送——发送仍由用户显式进行，装配面展开语义沿用「用户消息的斜杠技能展开」条文，接受补全前后的展开行为逐字节一致。

#### Scenario: 键入斜杠出候选，Tab 补全
- **WHEN** 生效技能含 `edge-skill`，用户在输入框键入 `/ed`
- **THEN** 面板出现且 `edge-skill` 在候选中（前缀/子序列命中）；按 Tab 后输入框文本变为 `/edge-skill `（尾部空格、光标在末尾），面板关闭，未发送任何消息，且焦点仍在输入框

#### Scenario: 子序列与大小写
- **WHEN** 用户键入 `/EGK`（大写、非相邻子序列）
- **THEN** `edge-skill` 以子序列命中出现在候选中（排在任何前缀命中之后）

#### Scenario: 零候选不吞键
- **WHEN** 面板可见但无任何命中（无匹配技能或空目录），用户按回车
- **THEN** 按键走原行为（Enter 仍发送当前文本、Tab 仍移动焦点），面板保持提示层语义

#### Scenario: 打出空白面板即关
- **WHEN** 面板可见时用户继续键入空格或任意正文
- **THEN** 面板消失，输入行为与无补全时完全一致

#### Scenario: Esc 不改写
- **WHEN** 面板可见时用户按 Esc
- **THEN** 面板关闭，输入框文本保持 `/ed` 原样，焦点仍在输入框

#### Scenario: 有正文后不弹
- **WHEN** 输入框文本为 `/ed 正文`（首段后已有文本），用户把光标移回首段
- **THEN** 面板不显示（首段后存在文本），不发生接受替换、正文不受影响

#### Scenario: 空目录空态提示
- **WHEN** 生效技能集合为空，用户键入 `/`
- **THEN** 面板显示一行中性空态提示（精确串「装一个技能后这里会自动出现候选（详见 skills.md）」），不出现任何候选行、不报错
