## 1. 先捕获红态：把"新标签页来得比等待窗口更晚"变成确定性复现

- [ ] 1.1 在 `test/integration/browser_worker_test.dart` 新增一条用例：页面里放一个链接 `id='slow'`，它 `target="_blank"`、点击处理器先 `preventDefault()`、再 `setTimeout(() => window.open('/landing'), 1500)` —— 也就是**新标签页必然在 1 秒窗口之后**才开。断言点击之后快照是 `LANDING` 页而不是原来的结果页（与既有那条"正常时序"用例同一套断言口径），并在断言前把现场打印出来（点击返回的 JSON、记录通道的行数）。
  **判据**：在**还没改** `scripts/browser_worker.py` 的代码上跑这一条，必须**稳定失败**（不是"有时红"）：连跑 3 次都是红。把 3 次的输出都贴出来。这一条是本变更的 red，也是将来的守卫。

## 2. 改 worker：跟随新标签页不再依赖那个固定短窗口

- [ ] 2.1 点击前判断"这个元素会不会开新标签页"：读目标元素的 `target` 属性（`_blank` 或具名/新窗口目标）。**读取失败（选择器不匹配、元素已被移除、读取超时）一律按"不会开新页"处理，绝不让判断本身的失败导致点击失败。** 判据：新增一条用例 —— 用一个不存在的选择器点击，断言返回的错误仍是"选择器超时/找不到元素"这一类，而**不是**判断过程抛出来的异常；贴实际输出。
- [ ] 2.2 判定"会开新标签页"时，这一次点击改用更长的**有界**窗口 `NEW_TAB_WAIT_SEC = 5`（秒）；其余点击继续用现在的 1 秒。窗口是上界：新页一到立即返回。判据：1.1 那条用例由红转绿；并加一条"普通点击不多等"的用例 —— 点一个原地跳转的链接，断言它的耗时不超过现在那条路径的量级（给出实际耗时数字，别只写"没变慢"）。
- [ ] 2.3 不管判定结果如何，超时之后补看一眼"页面集合是不是多出来一个"：点击**之前**记下 `context.pages`，超时后再取一次，多出来的那一页就跟随（覆盖"锚点没有 `target`、由 JS 开新页"这一类）。判据：加一条用例 —— 链接没有 `target="_blank"`，点击处理器 `preventDefault()` + `setTimeout(window.open, 1500)`；**若这一层实测有效**则用例绿、**若无效**（本机 Playwright 看不到晚到的弹窗）则按 4.1 如实标注并把这条用例删掉，两种结果都要贴输出。
- [ ] 2.4 "判定会开新页、但窗口与补看都没等到新页"时，往既有的记录通道（stderr 的 `browser-record:`）记一条。**不得**把它写进模型可见的返回内容，**不得**把它变成失败。判据：加一条用例 —— 一个 `target="_blank"` 但处理器里 `preventDefault()` 且**不开窗**的链接，断言①点击仍返回成功、②记录通道里出现"判定会开新页但没等到"这一条；贴两次输出（记录行 + 返回内容）。
