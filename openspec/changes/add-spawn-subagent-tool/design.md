## Context

当前 `Agent` 已拥有独立上下文句柄、不可变生效配置、消息历史、模型—工具循环、取消和计量，`AgentFactory` 与 `AgentRegistry` 也已统一创建和登记实例。仍有四个直接影响子 Agent 的现状：

- `Agent.send` 返回 `void`，模型错误与取消只改变内部流程，调用方拿不到结构化最终结论。
- 当前生产创建路径把上下文工作区默认设为 `ConfigService.homeDir`，既有 `setCurrentWorkspace` 测试入口可以设置其它目录；上下文只有 `set_workspace`，没有按句柄读取实际值的 Dart/C++ 接口。子 Agent 若只是再次写入主目录，就把“父子工作区相同”建立在一个当前默认值上，而不是继承父句柄的真实状态。
- `SessionRepository.list` 返回全部会话；若直接为子 Agent 创建普通会话，子运行会混入左侧列表并在启动时被恢复成独立 Agent。
- 工具循环逐个等待工具完成，因此第一版同步子 Agent 不需要另建调度器，也不会自然形成并行执行。

本设计复用现有 Agent 和上下文设施，不引入另一套执行概念。子 Agent 是一次性运行记录，不是可长期交互的新聊天。

## Goals / Non-Goals

**Goals:**

- 让配置了 `spawn_subagent` 的父 Agent 创建一次性子 Agent，指定完整任务，并可选择子 Agent 模板。
- 子 Agent 使用自己的上下文、消息历史、配置快照、取消状态和计量；父 Agent 不读取或复制子 Agent 的中间对话。
- 子 Agent 继承父 Agent 当前工作区，并使用与父 Agent 相同的 provider 解析和模板校验路径。
- 父 Agent 获得最终回复或明确失败；取消、销毁和异常路径均不留下仍在运行的子 Agent。
- 子运行记录可持久化诊断，但不混入普通会话列表，也不在应用启动时自动恢复执行。
- 保持模板工具过滤有效：未配置 `spawn_subagent` 的 Agent 看不到该工具。

**Non-Goals:**

- 不做子 Agent 再开子 Agent；不为递归深度另设数字限制。
- 不做并行子 Agent、异步消息、长期驻留、任务队列或群聊。
- 不做新进程、命令行程序、跨进程协议或另一套模型执行循环。
- 不做子 Agent 专用详情界面、运行记录删除界面或模板字段的任意实例覆盖。
- 不把子 Agent 的中间消息、思考、工具输出或 token 计量合并进父 Agent。
- 不为最终回复发明字符数、token 数或时长上限，也不静默截断最终回复。

## Decisions

### 工具契约采用同步的一次性调用

`spawn_subagent` 的输入为：

```json
{
  "task": "要独立完成的完整任务",
  "agent_type": "可选模板名"
}
```

`task` 必须是非空字符串；省略 `agent_type` 时使用父 Agent 的 `agentTypeName`，而不是固定使用 `general`。显式模板与缺省继承都先走 `AgentFactory.resolveCandidate`，模板缺失、provider 缺失、窗口非法或工具未知时不创建子上下文或子会话。

工具说明必须告诉父模型：子 Agent 看不到父对话，任务要自带必要背景；最终回复应是自包含结论，不能只留下子上下文自己的 `read_spill` 引用。需要持续使用的文件应写入继承的工作区。

成功结果保留结构化元数据，并以最终回复作为 `content`：

```json
{
  "ok": true,
  "content": "子 Agent 的最终回复",
  "child_session_id": "子运行记录 id",
  "agent_type": "实际模板",
  "model": "实际模型",
  "metering": {
    "input_tokens": 0,
    "output_tokens": 0,
    "total_tokens": 0,
    "requests": 0,
    "tool_calls": 0
  }
}
```

示例中的零只表示 JSON 形状，不是运行目标或上限。真实结果使用子 Agent 自己的计量。`child_session_id`、实际模板、模型和计量作为不含密钥的子运行元数据写入父工具调用的 `ToolCallActivity` 与 `toolCallsJson`，供诊断和验收读取；它们不进入父模型可见的 `tool_result.content`，父模型仍只收到最终结论。失败结果使用 `ok:false`、可区分错误和已知的 `child_session_id`，不得把错误文本包装成成功结论。

替代方案是立即返回运行 id 再轮询。该方案需要任务状态、异步消息和恢复调度，超出一次性“任务 → 结论”的目标，因此不采用。

### Agent 发送路径返回结构化运行结果，同时保持现有界面行为

新增不可变 `AgentRunResult`，至少区分完成、失败、取消和实例忙四种结果，携带最终文本、错误和本实例计量快照。`Agent.send` 改为返回该结果；现有界面仍可忽略返回值，现有消息写库、流式事件与错误消息行为不变。

最终文本只在“模型回复没有工具调用”的最终轮确定，不能从子历史里随便取最后一条消息，也不能把以 `Error:` 开头的错误消息当成成功结论。未预期异常要进入失败结果；已经写入界面的错误不得重复写库。

完成但没有最终文本时，子 Agent 运行器返回 `empty_final_response` 错误。父 Agent 的正常空回复行为不因本改变被强行改写。

### 子 Agent 仍由 AgentFactory 创建，但使用子运行配置副本

新增子运行服务负责协调，父 Agent 的 `_executeTool` 只增加一个分发分支。服务通过工厂创建子 Agent，不自行拼装 provider、摘要提供者或模型请求。

工厂在普通 `create` 的共享逻辑上支持子运行参数：

- 会话包含 `parentSessionId`，上下文句柄仍使用该子会话 id。
- 不传父界面的 `AgentCallbacks`，避免子流式文本直接进入父聊天。
- 在创建时复制并冻结生效配置；模板之后修改不影响已创建的子 Agent。
- 子配置的系统提示词附加“一次性子 Agent、无父历史、最终回复必须自包含”的角色说明。
- 子配置的生效工具清单排除 `spawn_subagent`，模板本身和父实例配置不变；子上下文快照记录实际排除后的清单。这样不是运行到递归调用时才静默失败，而是子模型一开始就不会拿到该工具。

运行器与工厂通过延迟回调连接，避免“工厂创建 Agent、Agent 又需要运行器、运行器再使用工厂”的构造循环。生产与测试必须走同一创建路径。

### 工作区通过只读接口继承

在 C++ 上下文接口和动态库增加 `get_workspace(handle)`，成功返回 `{"ok":true,"workspace":"..."}`，未知或已销毁句柄返回 `ok:false` 和 `unknown_context`，不隐式创建上下文。Dart `ISidecar` 与 `SidecarBridge` 暴露同一路径。

创建子 Agent 前读取父句柄的工作区，再把该值用于子上下文的初始化。不得假定父工作区等于应用主目录，也不得读取界面当前会话或另开一份全局工作区变量。读取失败时不创建子运行。当前生产默认值相同并不构成省略该接口的依据；非默认场景可通过既有 `setCurrentWorkspace` 测试入口真实构造。

Dart 桥把原始 JSON 解析放在一个可独立测试的内部入口，生产 `getWorkspace` 与单元测试共用该入口。真实 DLL 用例覆盖成功和未知句柄，解析入口用例覆盖非 JSON；不得为了制造错误而假造另一条生产执行路径。

### 子运行记录保留，但普通会话操作只处理顶层会话

`sessions` 增加可空 `parent_session_id`，普通会话为 `NULL`，子运行记录指向父会话。`Session.fromRow` 与 `toRow` 保留该字段；`SessionRepository.create` 只在子运行路径传入父 id。

`SessionRepository.list` 改为只返回 `parent_session_id IS NULL` 的顶层会话，继续按 `updated_at` 排序；另提供按父 id 查询子记录的只读入口供测试和后续诊断使用。启动恢复仍遍历普通列表，因此不会自动重建一次性子 Agent。子记录的消息和摘要仍使用现有按会话存储路径。

删除父会话时，子运行记录及其消息、摘要必须随父记录删除。验收使用真实 SQLite 数据库验证级联确实发生，不能只凭表结构里的 `REFERENCES` 字样断言；若当前连接未启用外键，必须在该任务内修正连接配置并覆盖既有会话删除行为。

第一版不提供查看子运行详情的界面。父对话现有工具卡片显示任务参数与最终结论；子记录保留在数据库中，不伪装成可点击的普通聊天。

### 运行关系由子运行服务持有，取消沿父子关系传播

子运行服务登记 `parent_session_id → 正在运行的 child_session_id`，运行实例仍统一放在 `AgentRegistry`。同一时间存在哪些子运行以这张关系表为准，不从界面状态推断。

- 单独取消子运行只取消该子 Agent；父 Agent 收到取消错误后可继续自己的模型循环。
- 父 Agent `cancel` 或 `dispose` 先取消其活动子 Agent，再取消自己的请求；第一版无下一层子 Agent，因此不需要递归遍历。
- 父 Agent `retire` 继续遵守模板切换契约：不取消在途整轮，等待子调用和父整轮自然结束后再让位。
- 子 Agent 结束后，在 `finally` 中等待其整轮、销毁子上下文并从运行注册表移除，然后解除父子关系。子会话数据库记录不因上下文销毁而删除。
- 父会话删除和应用关闭沿用父 Agent 销毁路径，不能绕过子取消直接删库。

子上下文销毁会按既有契约清理该子上下文的 spill 文件和浏览器资源，因此最终回复必须自包含。父上下文自己的 spill 序号、文件和浏览器状态不受子销毁影响。

替代方案是让 `AgentRegistry` 自己推断父子关系。注册表当前只负责按句柄管理实例，把任务关系塞进去会混淆运行实例目录与一次性调用生命周期，因此关系由子运行服务单独持有。

### 最终结论完整回传，不新增输出截断协议

子 Agent 的中间历史只写入子会话；父 Agent 只收到一次 `spawn_subagent` 工具结果。最终回复作为该结果的完整 `content` 回传，不按新数字截断，也不额外调用模型摘要。

完整保留必须同时覆盖当轮工具结果与之后的历史重建。`Agent._buildApiMessages` 重放 `spawn_subagent` 工具结果时 SHALL 直接使用保存的完整 `result`，不得调用通用 `elideOversizedToolResult`；其它工具继续沿用既有截断和取回规则。验收必须在首次父请求之后再次发送并重新恢复历史，不能只比较运行器即时返回的 `content`。

这意味着过长的最终回复仍会占用父上下文，包括后续历史重放。第一版通过工具说明和子角色说明要求“只交付结论”控制输出，而不以静默降级冒充上下文隔离。若以后要为大结论引入 spill，必须另立 change，给出父上下文可读引用和完整取回路径。

### 首启默认增加工具，既有十项清单不自动迁移

`ToolCatalog.kBaseToolNames` 增加 `spawn_subagent`，新首启配置使用包含该工具的当前默认清单；旧两项首启清单仍按既有可见迁移规则升级到当前默认清单。

不对上一版十项完整清单做自动迁移。原因是“旧版默认十项”与“用户从新版十一项中主动删除 `spawn_subagent`”在磁盘上完全相同，现有配置没有可区分两者的迁移标记；自动升级会把用户选择重新覆盖。所有既有模板，包括恰好是旧十项形状的模板，都保持原清单，用户在模板编辑器中显式添加后才获得该工具，显式移除后也不得被加回。

迁移不得删除未知工具，也不得把 provider 密钥写进提示或日志。

## Risks / Trade-offs

- [父 Agent 等待期间子 Agent 出错，若发送接口仍只返回 `void`，错误会被伪装成空结论] → 先实现结构化 `AgentRunResult`，集成测试覆盖模型失败、取消、空回复和实例忙。
- [子 Agent 直接复用普通会话列表会污染侧栏并被启动恢复] → 增加父子字段、真实数据库迁移测试和启动恢复测试。
- [只继承模板却不继承实际工作区，会让子工具在用户主目录执行] → 增加按句柄查询接口，并在集成测试中让父子工作区不同以检出错误继承。
- [父取消只取消父句柄，会留下子模型请求或长命令] → 父取消先落到子运行服务，测试同时断言两个上下文的取消与后续清理顺序。
- [子 Agent 最终回复引用自己的 spill，子上下文销毁后引用失效] → 工具和角色说明要求自包含结论；测试断言子销毁不删除父 spill，文档明确该限制。
- [同步调用会延长父工具卡片等待时间] → 保留现有流式等待与取消行为，不引入不可取消的后台任务；并行执行留到后续独立变更。
- [完整最终回复仍可能很大] → 明确不截断、不伪造“只增加少量 token”的保证；后续如需大结论交付，复用可恢复的输出契约另行设计。

## Migration Plan

1. 数据库版本由现有 7 升到 8；`_onCreate` 与 `_onUpgrade` 同时增加 `sessions.parent_session_id`，既有行保持 `NULL`，消息、摘要和会话 id 不改写。
2. 动态库新增只读 `get_workspace` 符号；先同步构建并刷新仓库根的 `sidecar.dll`，再运行 Dart 测试，避免旧库造成符号缺失。
3. 新首启配置写入包含 `spawn_subagent` 的当前基础清单；配置加载只对旧两项首启形状继续既有可见迁移，不自动改写既有十项或其它自定义模板。写回时保留其它 provider、search、spill 和模板字段。
4. 回滚不执行删除列或清空子记录的降级迁移。代码回滚不得擅自删除数据库新增列；不得在唯一用户数据库上试验旧版本兼容性。
5. 用户文档说明子运行不可恢复执行、普通列表不可见、不能嵌套以及同步等待行为。

## Open Questions

无。第一版按上述同步、不可嵌套、保留子记录但不提供详情界面的边界生成规范和任务；若这些边界改变，应先修订本 change，再进入实现。
