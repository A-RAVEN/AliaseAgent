## Why

现在界面上只有一条「正在压缩」的提示，用户看不见当前这一轮请求里**原文、一级摘要、二级摘要各占多少**，也看不见离模型窗口装满还有多远。压完之后想知道哪些内容被换成了摘要，只能切到「真实上下文」那一屏逐条读。

## What Changes

- 顶部工具栏（「对话视图 / 真实上下文」那一行的右侧）新增一个圆环指示器：
  - **整圈 = 模型上下文窗口**（配置里的 `max_context_tokens`）。
  - 环上的弧 = 这一轮真正发出去的内容，**按上下文顺序从 12 点顺时针排**：二级摘要 → 一级摘要 → 原文，三段首尾相接。
  - 三段长度各按自己的 token 数相对窗口计算，**三段加起来就是这一轮的占用**；剩下的空圈是剩余窗口。
  - 没有任何摘要时，一级、二级两段长度就是 0，环呈现为一根单色弧 —— 如实显示，不做视觉补偿。
- 点圆环弹出一个只读面板，逐行列数字，每一行标出来源：
  - 二级摘要、一级摘要：模型返回的实测输出 token；
  - 原文：按仓库既有的估算器（4 字符 ≈ 1 token）算；
  - 系统提示词 + 工具定义：**不占环上颜色**，面板里单列一行；
  - 合计：上面各项相加，并写明环画的是「对话消息」那部分、不含系统提示词与工具定义。
- 构建请求时把这份拆分**与已有的「真实上下文快照」在同一时刻、同一次 setState 里记录下来**，面板读的就是它，不在界面上重新解析文本猜层级。
- `max_context_tokens` 缺失或 ≤ 0 时不画圆环（与「真实上下文」快照缺失时那一屏的处理一致）。

## Capabilities

### New Capabilities

- `context-occupancy-ring`: 上下文占用圆环 —— 环的三段拆分口径、记录时机、面板里每一行的数字与来源标注、窗口缺失时的行为。

### Modified Capabilities

（无。压缩的阈值、触发、分层机制一个字都不改；这个变更只增加一个显示，不改变任何既有要求。）

## Impact

- `lib/main.dart`：`_callModel` 里请求构建完成（`apiMessages` 已定）之后记录三色拆分；`ContextSnapshot` 的构造点同步带上它。
- `lib/services/context_snapshot.dart`：`ContextSnapshot` 增加一个字段承载这份拆分（新字段带缺省值，既有构造点与既有测试不受影响）。
- 新增 `lib/ui/context_ring.dart`：圆环本体（自绘）+ 点击弹出的面板。
- `lib/ui/` 的顶部工具栏接线（`ChatScreenState.build`）。
- 用户文档：`Docs/user-guide/context-compaction.md` 增加「环怎么看」一节；`README.md` 若有相关索引行同步。
- 测试：`test/unit`（三段拆分的纯计算）、`test/widget`（环与面板的渲染）、`test/integration`（投影之后记录下来的拆分与实际发出的内容一致）。
- 复杂度：低。不碰 C++ 侧、不碰压缩算法、不新增配置项。
