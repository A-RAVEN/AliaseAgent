# 设计：成员自我身份锚 + 名点识别

## 背景与根因

群聊成员的系统提示词由模板提示词 + `kGroupMemberRolePrompt` 组成。后者只写「你是一个
群聊组的成员」，没有名字；`member.name` 只进入**视图渲染**（把别人的公开行标成
「X 说：」），从未进入**成员自己的**系统提示词。因此：

- 用户说「丙讲个笑话」时，乙和丙看到的都只是一句普通用户消息，没有信息告诉它们
  「丙」是不是自己；
- 再叠加「默认沉默」提示词，乙可能把「讲笑话」当成给自己的任务而抢讲，丙可能认为
  与自己无关而沉默；
- 显式 `@丙` 由核心解析成 mention 强制轮，能兜住一部分场景，但裸名点名没有这层兜底。

结论：这不是调度或提示词「语气」问题，而是**成员身份信息缺失**。修复必须把成员自己的
显示名注入系统提示词，并让反应提示词明确「点名别人 / 点名自己」的处理。

## 决策

### D1 身份锚：参数化常量 + 成员实例创建时注入

新增 `kGroupMemberIdentityPrompt(String name)`，返回：

> 你就是「{name}」本人。在本群里，别人用「{name}」称呼你（@{name} 或直接叫「{name}」
> 是在跟你说话，叫别的名字是在跟别人说话）；但**你自己发言时直接以第一人称「我」
> 说话**——「{name}」只是别人叫你的方式，不是你对自己的称呼。**不要称自己为
> 「{name}」**，不要在正文给自己署名（如「{name}：」「{name}（作者本人）：」
> 「作为{name}」）——系统会自动把你的发言标为「{name}」。模板提示词里的任何自称或
> 角色名都不代表你在本群的身份。

**不把模板名当身份**：已核对 `sidecar.sendMessage` 的 payload（`systemPrompt` /
`messagesJson` / `toolsJson` / `model` 等）与 `Agent._callModel` 的 systemPrompt 组装，
`agentTypeName` 只进 `ContextSnapshot.agentType`（UI 快照），不进入模型可见处；但模板
自己的 `systemPrompt` 可能自称角色名（如 general 模板写「你是 general 助手」），这会与
群内名冲突。身份锚用「**第一人称本人视角**（你就是{name}本人；{name} 只是别人叫你的
方式，不是你对自已的称呼）/ 模板自称不代表本群身份」压住这个冲突，同时**保留**
模板 systemPrompt 的业务内容（那是模板作者写的，不能删）。

注入点选 `AgentFactory.createMember`（`agent_factory.dart`）——它已经在同一处把
`kGroupMemberRolePrompt` 叠进实例配置副本（`resolved.copyWith(systemPrompt: ...)`），
`member.name` 在这里可得，且不会改模板本身。顺序为「模板提示词 → 身份锚 → 组角色说明」：

- 身份锚放前面，模型先知道「我是谁」；
- 角色说明紧随其后，继续承担自包含、他人「X 说」投影、共享工作区等纪律；
- 身份锚对**所有组成员轮**（定向 / mention / 自愿反应）生效，不区分是否反应轮；
- 单会话与关闭态纯 speaker 的普通轮不经过 `createMember`，行为逐字不变。

身份句必须参数化，而不是写死「你是一个群聊组的成员」后再拼名字字符串——参数化让单测能
逐字断言 `kGroupMemberIdentityPrompt('甲')` 出现、并且 `kGroupMemberIdentityPrompt('乙')`
不出现，防止「把别人的名字当成自己」。

### D2 名点识别：写进自愿反应提示词，靠身份锚判断

`kGroupReactionPrompt` 增加一段名点识别纪律：

- 最新消息点名**其他成员**（`@别人` 或直接叫别人名字）时，除非你有别人没说过的实质性
  补充，否则返回 `pass=true`；
- 点名的是**你**（叫你的名字或 `@你`）时，应当回应：`pass=false` 并给出实质内容。

它不新增工具、不新增 RPC 字段，也不改变默认沉默框架：沉默仍是常态，名点只是「相关性
门槛」的具体化——被点名是强相关，点名别人是弱相关。身份锚提供「我叫什么」，这段纪律
提供「名字出现时怎么判断」。

### D3 `@mention` 定向保持不变

`parseMentionedMemberIds`、`group.send` 的 `speaker`、mention 强制轮、`group_react`
结构化判定全部不改。显式 `@丙` 仍由核心解析成强制轮（必应）；裸名点名（没有 `@`）不是
新解析器，而是「身份锚 + 自愿反应」自然产生的行为。这样：

- 不引入第二套名字匹配规则，不会与 `@` 解析漂移；
- 用户显式点名仍是最可靠的定向方式；
- 裸名点名的质量取决于模型是否遵守提示词，属于经验性改善而不是硬保证。

### D4 群成员名单：每轮现读注入系统提示词（不选工具）

在 `Agent._callModel` 每轮装配系统提示词时，通过 `groupRosterProvider` **现读**当前组
成员（`GroupMemberRepository.listByGroup`，过滤 `isRemoved`），把
「本群成员：甲、乙、丙。你是「丙」。」追加到模板提示词之后、`guard.inject()` 之前。
选择名单注入而不是 `group_members` 工具的理由：

- 成员是**小群、低频变更**，每轮一次 DB 读足够便宜；模型每轮都能直接看到名单，不需要
  先「想起来调工具」；
- 工具是**可选调用**，模型可能不调；名点识别需要的是默认上下文，不是可查能力；
- 每轮现读保证成员增减**下一轮即生效**，不需要重建实例，也不会把名单缓存成旧值；
- 已移除成员不进当前名单（历史公开行的归属仍由 `displayNamesOf` 保留，二者职责不同）。

注入点放在 `_callModel` 而非实例创建处，是为了「每轮新鲜」；单会话（`member == null`）
不注入，普通轮行为不变。

### D5 不替其它成员发言：精确界定「禁冒充」与「允许引用回应」

在 `kGroupMemberRolePrompt`（所有组成员轮）与 `kGroupReactionPrompt`（自愿反应轮）同时
写入同一条纪律：

- **禁**：替其它成员发言、编造他们的观点或立场（其他成员会自己说，编造出来的是假归属）；
  抢答**点名其它成员**的问题（那是给他们的，让他们自己答）；在一条回复里模拟多个成员的
  对话/轮流发言。
- **不禁**：引用、回应、反驳别人**实际说过**的话（这是群聊该有的实质互动，也是有效的
  贡献）；同意/反对别人的具体论点；指出别人前后矛盾。过度限制「引用回应」会扼杀实质反应，
  所以纪律必须写成「禁冒充、不禁引用」。

三者互补：身份锚回答「我是谁」，名点识别回答「这条点名是不是给我的」，本条回答「我说话
时只能代表我自己」。与「默认沉默」不冲突：不替别人发言不等于必须说话，只是说话时不许
越界代答。

### D6 第一人称发言：禁自我署名，系统自动署名

用户实测另一种口吻问题：成员把自己的公开发言写成第三人称旁白，例如「丙（作者本人，补
三条甲乙都没覆盖的）：……」「作为丙，我认为……」。根因是角色说明只说了「别人的公开
回复以『某某 说：』出现」「自己的历史是 assistant 轮」，却**没说「你自己说话时用第一
人称『我』、不要给自己贴署名」**；模型于是模仿别人的归属格式，给自己加上「丙：」标签。

修复写进三段提示词（`kGroupMemberRolePrompt`、`kGroupReactionPrompt`、
`kGroupMustRespondPrompt`）与身份锚：

- 用第一人称「我」直接发言——你就是本人正在说话，不是旁白描述「某某 会怎么说」；
- **不要在 message 正文开头写自己的名字或归属标签**（「丙：」「丙（作者本人）：」
  「作为丙，我…」）；
- 公开行由系统按 `author` 自动署名（时间线显示显示名），模型不需要也不应该自己写；
- 引用别人时仍可用「甲说… / 乙提到…」，但说自己一律用「我」。

产品侧**不做事后文本清洗**：提示词纪律负责口吻，`author` 字段负责归属；测试断言公开行
原样保存 message、不自动添加「甲：」前缀，同时提示词逐字含纪律。

### D7 评价对象尚未出现：等待，不编造

用户实测另一类幻觉：用户说「丙讲个笑话，甲和乙评价」，丙还没讲，甲就凭空编了一个
「笑话 v2」并引用不存在的 `joke_scores_jia.md` 来评价。根因是自愿反应轮的「评价」任务
驱动模型立刻产出内容，而评价对象还不存在。

修复写进 `kGroupReactionPrompt`、`kGroupMemberRolePrompt` 与 `kGroupMustRespondPrompt`：

- 如果被要求评价/回应/处理的对象**尚未出现**（别人还没讲笑话、还没给方案、还没贴正文），
  返回 `pass=true` **等待它出现**；
- **不要凭空编造一个对象来评价/回应，不要假装读了不存在的文件，不要自己造一份再评**；
- 等该对象作为新的公开消息出现后，会在后续轮看到它，那时再反应；
- 这条**优先于名点识别**：即使点名的是你，对象还没出现也先 `pass=true`，不要用编造填充；
- 强制轮（`@`）例外口径：必须回应，但对象不存在时如实说「还没看到 X，请 X 先给出」，
  不得编造。

与「名点识别」的分工：名点回答「该不该由我接」，本条回答「现在有没有东西可接」；两者
同时成立才发言。live 用「丙讲笑话，甲乙评价」验证：第一轮甲乙 `passed`、丙 `replied`，
后续轮甲乙评价丙实际讲的那段，公开文本不得出现假文件名。

## 风险与权衡

- **模型可能仍不遵守**：身份锚与名点纪律都是提示词，不能 100% 保证丙一定回应。live 用
  真实模型验证一次；若模型不遵守，退化行为是「该说话的人沉默 / 别人多说一句」，不会
  产生错误归属（公开行 `author` 始终由实际运行的成员决定）。
- **身份句与改名**：成员改名会重建实例，身份锚用新名字重建；历史公开行作者 id 不变。
- **提示词变长**：每个成员每轮多一句身份说明，token 成本可忽略；且不影响普通轮。
- **不做的事**：不在核心做「裸名 → 成员 id」的硬解析（会与 `@` 解析、重名规则冲突，
  也违背「名字只在渲染归属时解析」的既有边界）；不把身份锚写进模板（模板是共享的，
  身份是成员实例私有的）。

## 测试策略

- 单元：`test/unit/group_prompts_test.dart` 断言 `kGroupMemberIdentityPrompt('甲')`/
  `（'乙'）` 的逐字内容与互不相等；断言 `kGroupReactionPrompt` 含「点名其他成员」「点名
  的是**你**」「应当回应」等名点纪律。
- 集成：`test/integration/agent_reaction_round_test.dart` 创建甲/乙/丙三个实例，断言各自
  系统提示词含自己的身份句、不含别人的身份句；再用假 sidecar 编排「丙讲个笑话，甲和乙
  评价一下」：第一轮甲/乙 `passed`、丙 `replied`，首个公开成员行 `author=丙`。
- live：`integration_test/group_reaction_live_support.dart` 第一段改为「丙讲一个笑话，
  甲和乙分别评价一下」，断言第一个成员公开行的 `author` 是丙；仍然观察沉默率与
  `all_passed`/`round_cap`，并截图。
- 文档守卫：`test/unit/group_docs_test.dart` 断言用户文档写了「成员知道自己的名字」
  「裸名点名」「点名别人默认沉默」。
