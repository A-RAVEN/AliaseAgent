## Why

现在的助手能读代码、能改文件，但**执行不了任何命令** —— 改完只能靠人跑测试、跑构建、跑 git，助手自己看不到结果。缺了这一环，助手对"我这次改动到底对不对"没有任何判断依据，只能把验证推给人。

本机已经具备实现条件：sidecar 里有一个通用的子进程执行器（`subprocess::run`，带工作目录、超时、超时杀整棵进程树），`web_fetch`、`glob_file`、`grep_file`、浏览器可用性探针都走它，但没有任何一个工具把它暴露给模型。

## What Changes

- 新增 `run_command` 工具：模型给一条命令字符串、一个可选的超时毫秒数、一个可选的工作目录，工具把命令跑起来并把退出码、标准输出、标准错误还给模型。
- **命令按参数数组递进操作系统，不经过命令行解析。** 具体做法是把命令字符串作为 `-Command` 的**单个参数**交给 PowerShell（`["powershell.exe","-NoLogo","-NoProfile","-NonInteractive","-Command","<命令>"]`），由 PowerShell 自己解析这条命令；不额外套一层 `cmd /c`。这样"外层"不存在二次解析，引号与特殊字符只在 PowerShell 这一层起作用。
- **一种方言一个工具**：本工具固定为 PowerShell 方言（原生路径、`$env:NAME`），不做 bash/方言翻译，也不让调用方选择 shell。
- **每次调用前拼一段固定的编码前缀**（把控制台输出编码钉成不带 BOM 的 UTF-8），并给子进程注入 `NO_COLOR=1`、`PAGER=cat`、`GIT_PAGER=cat`，让中文输出不乱码、不让翻页器把进程挂住。
- **输出有上限，只保留尾部**（错误与结论通常堆在末尾），超出上限的完整输出写进系统临时目录并把路径告诉模型；返回文本里明写"截断了、全文在哪"，不静默丢内容。
- 超时：调用方给的毫秒数有缺省值与上限，到点终止该进程**及它拉起的全部子进程**（毫秒数要能真的按毫秒生效，不能因为下游只支持整秒而被截断）。
- 新增四个配置项（缺省超时、超时上限、每条流的内存上限、完整输出的写文件上限），写进 `~/.aliasagent/config.json` 的 `agent_types.general` 段。
- 为了让上面两件事成立，`subprocess` 执行器要加三个能力：宽字符启动（现代码把 UTF-8 字节直接交给按 ANSI 码页解释的接口，中文命令行与中文工作目录在本机就是坏的）、毫秒级超时、注入额外环境变量。三个都做成"不传就与今天完全一样"，既有调用方的行为不变。
- 同步用户文档：新增一份说明本工具用法与限制的中文文档，并登记进 `README.md` 的功能索引。
- 新增三层测试：C++ 单测（命令构造、编码前缀、环境变量、输出取舍、毫秒超时、工作目录）、Dart 集成测试（经真实 DLL 跑真命令，并穿过配置组装路径）、文档一致性检查（新工具名与配置键必须能在工具定义与代码里核到）。

## Capabilities

### New Capabilities

- `command-tool`: 助手执行命令行程序的能力 —— 工具的参数与返回、命令怎么递进操作系统（参数数组、不经二次解析）、用它的时候是哪种方言、编码怎么钉死、输出怎么设上限与截断、超时与进程树终止、以及四个配置项（含它们怎么随每次调用到达执行侧）。
- `command-tool-tests`: 上述能力的可失败验证方式 —— C++ 单测覆盖命令构造与输出取舍、Dart 集成测试经真实动态库跑真命令、以及"文档里的工具名与配置键必须与代码一致"的一致性检查。

### Modified Capabilities

- `user-documentation`: 三处改动 —— ①"用户可及的功能"的清单加上"命令行工具"这一项，"模型可调用的工具"那份举例列表（`read_file` … `browser_snapshot`）加上这个工具的名字；②"配置键必须能在解析路径里核到"这条的举例要加上本次新增的四个键；③新增一条场景：描述本工具的文档必须写明"命令是在本机用你自己的权限真实执行的、能改动工作区里的文件、没有沙箱、跑起来之后不能事后批准或撤销"。

## Impact

- **新增**：`sidecar/src/command_tool.cpp` / `.h`（工具本体）、`sidecar/test/command_tool_test.cpp`、`test/integration/command_tool_test.dart`、`Docs/user-guide/tools-command.md`。
- **改动**：`sidecar/src/subprocess.cpp` 与 `sidecar/src/subprocess.h`（Windows 启动改走宽字符接口 + 毫秒级超时 + 可注入额外环境变量，三项都做成"不传就与今天一样"）、`sidecar/include/sidecar_api.h`（新增 FFI 入口 `run_command` 的声明）、`sidecar/src/sidecar_api.cpp`（实现该入口）、`sidecar/CMakeLists.txt`（生产源码列表加一个文件、测试源码列表加两个文件 —— 新工具与新用例）、`lib/services/sidecar_bridge.dart`（FFI 声明 + 在 worker isolate 里执行，避免界面卡住）、`lib/main.dart`（工具定义 + `_executeTool` 分支，把四个配置值组装进请求）、`lib/models/agent_type_config.dart`（四个配置项）、`README.md`。
- **顺带修掉的两处隐患（前置修复）**：①`subprocess` 的 Windows 启动目前用 `CreateProcessA`，命令行与工作目录都按 **ANSI 码页**解释，而本机 ANSI 码页是 1252（控制台码页 65001 是另一回事），所以中文命令行与中文工作目录**今天就是坏的**；②`Options` 只有整秒超时、也没有环境变量入口，装不下"毫秒超时"和"禁掉颜色/翻页器"。这两处修完，所有走 `subprocess::run` 的既有调用方（`web_fetch`、`glob_file`、`grep_file`、浏览器探针）一并受益。
- **一处不修但记账**：`sidecar/src/browser.cpp` 里另有一套自己的进程创建（另一处 `CreateProcessA`，不走 `subprocess::run`），因此浏览器工作进程不受本次改造保护；本变更不改它，只把它记进 `Docs/known-bugs.md`。
- **不改**：`web_search` / `web_fetch` / 浏览器工具的既有行为；subprocess 执行器的**调用方式**（既有调用方一行都不用改，新能力都是选填字段）。
- **已核实、但不在本变更范围内的一处既有缺陷**：配置里的 `agent_types.<名>.tools` 列表被解析、被写回，但**从未用来过滤发给模型的工具定义** —— 全 `lib/` 范围内没有一处读它做过滤（只有 `AgentTypeConfig` 自己的定义与序列化）。因此 `run_command` 与 `read_file`、`glob_file` 一样，是**无条件出现在工具定义里**的。本变更按既有事实写（工具无条件可用），并把这条缺陷记进 `Docs/known-bugs.md` 另行安排，不在本变更里顺手改（记这条本身是一条任务）。
- **风险（明写，并接受）**：这个工具让模型能在工作目录下执行任意命令，没有确认弹窗、没有权限分层。这是"助手能自己验证"的必然代价，本变更不引入任何自加的门禁（工作目录参数那道边界检查是"参数填写规范"的一致性要求，不是安全边界，也不是本变更发明的门禁）。缓解手段只有两条：命令的来源是用户自己的对话，以及工具的说明文字里写清"命令在工作目录下真实执行、会真的改动磁盘"。
- **一处诚实标注的未知**：命令里带中文参数时，**子进程能不能原样收到**目前没有实测结论（我们这一侧不再弄坏字节是确定的，子进程按什么编码读自己的命令行不由我们决定）。实施第 1 组的探针会给出结论；在给出结论之前，用户文档里不许写"支持中文参数"，只写测出来的结果。
