## Why

点一个会开新标签页的链接（`target="_blank"` 或 `window.open`）时，浏览器 worker 只等 **1 秒**（`scripts/browser_worker.py` 的 `NEW_PAGE_WAIT_SEC`）就断定"这次是原地跳转"，于是**不跟随新标签页**、快照停在被点的那张原页面上。只要新标签页注册得比 1 秒更晚，这个判定就错。后果有两层：

- **产品层**：AI 以为自己在看搜索结果页，实际上真正的落地页它一次都没看到（点进去的内容读不到）。
- **验证层**：`test/integration/browser_worker_test.dart` 里那条"点 `target=_blank` 要跟随新标签页"的用例，**单独跑必过、跟着全量套件跑约一半概率失败**（全量时机器负载高得多），让"全量测试全绿"这个验收口径变得不可信。

**根因的立场（本设计如实标成推断）**：全量时"新标签页注册得比 1 秒更晚"这个解释**在本机没有读数支持** —— 唯一一条注册耗时实测是 worker 里 `NEW_PAGE_WAIT_SEC` 注释写的 **0.16–0.36 秒**（1.0 秒是它的 2–6 倍余量），而且那次是在没有负载的单文件运行下量的。所以本变更按"等待窗口在负载下不够长"这一条最可能的解释去修，并用一条确定性的用例证明"窗口长度确实决定了一条晚到的新页会不会被跟随"；真实全量间歇失败的成因，本变更不做断言。

这条缺陷是 2026-09-20 在做另一个变更（上下文压缩阈值，已归档）时被暴露出来的；当时我判断错了根因（以为是"读取时机"而不是"等待窗口太短"），还改了一处**等价于没改**的代码，已撤回。现在按真实根因单独立项。

**2026-09-20 对抗审查后修订过一版**，改掉了三处会让人白干的设计（依据都写在 `design.md`）：

1. 原方案里"超时后再看一眼页面集合"这一层**删掉了** —— 它看的时间点早于晚到的弹窗（算术上必然看不到），而且这个做法在归档变更 `2026-09-13-add-browser-tool` 里**已被实测否决过**。
2. 原方案在 proposal 里写"1 秒窗口不变 + 有界轮询"，与 design 的"判定会开新页就用 5 秒窗口"互相矛盾 —— 统一成后者。
3. 原方案写"给既有条文补上稳健性要求"，但 delta 用的是新增需求，归档后既有条文一字不改、两句相反的话会并存 —— 改成**整块改写既有条文**（`## MODIFIED Requirements`）。

**2026-10-03 第二轮对抗审查后修订过一版**（本轮审查是五路独立审查 + 五路交叉证伪，全部结论都由本机文件核实），改掉的是会让实现者白干或让判据失效的地方：

1. **取页方式原先没写死**：design 只说"点击返回之后再有界地等新页事件"，并附一句"点击期间就已注册的新页由点击前页面集合这一层兜住"。本机 Playwright 的事件监听是**调用时才挂上**的，点击期间就已冲洗掉的页面事件，点击之后挂的等待者永远等不到 —— 只写等待，每一次普通 `target=_blank` 点击都要白等满 5 秒并被记成"该开没开"；只核名单，则 1.5 秒那种晚到的新页接不住。现在写死成三步（点击前记基准 → 点击返回后立刻核一次名单，有就立即跟随 → 没有才进入有界等待，等待到期后再核一次），并要求两条能失败的判据分别钉住两个方向。
2. **红态与绿态的断言原先自相矛盾**：任务 1.1 要求同一条用例既断言点击记录的 `adopted_tabs > 0`（改完之后的绿态口径），又断言 `adopted_tabs == 0`（未改代码时的红态归因）。改完后这个键必然是 1，那条断言让用例永远不可能转绿。现在把红态归因明确成**只打印、不写成断言**，并补上"第二次 snapshot 之前显式等 2 秒"。
3. **记录键原先没有生命周期**：新增的 `expected_new_tab_unfulfilled` 只写了"挂在会话属性上"，没有一条要求它复位 —— worker 是长期存活进程，一次没等到会让之后每一次点击的记录都带 `true`。现在写死"每次点击开始先复位"，并加一条不复位必红的判据。
4. **规范 delta 漏了三处义务与一个既有事实**：整块改写既有条文时，"具名 / 新窗口目标也走长界""两个界都是上界（到页即返回）""记录键不得进模型可见内容"原先只写在括注里、七个场景一个都不覆盖；而"这次等待从点击返回之后起算"这一条根本没写进规范。现在提成独立条款并各补场景。
5. **验证层原先缺两层**：CLAUDE.md 的验证清单有五层，tasks.md 只覆盖三层（分析、全量测试、live），C++ 构建与 `ctest`、整套冒烟一层都没有。现在补上，并要求如实区分"改动前就红"的项目。

## What Changes

- **点击前先判断这个元素会不会开新标签页**：worker 在点击前读一次目标元素的 `target` 属性（`target="_blank"`，或等价的具名/新窗口目标）。这次读取**不等待元素、且有明确的小超时**；读不到、读失败、超时一律按"不会开新页"处理，绝不让判断本身把点击弄失败。
- **判定会开新页 ⇒ 这一次点击用更长的有界窗口**：`NEW_TAB_WAIT_SEC = 5` 秒；其余点击继续用现在的 1 秒。两个窗口都是**上界**：新页一到立即返回，**不许**等满。**窗口从点击返回之后起算**（现在的代码是从点击之前起算，慢点击会把弹窗预算吃掉）。
- **取页方式写死成三步**：点击前记下"会话里由页面处理器登记过的浏览器打开的页"名单（既有的 `on("page")` 处理器改成同时登记页对象）→ 点击返回后**立刻**核一次名单，有新增就立即跟随、不进入等待 → 名单没有新增才进入有界等待新页事件，等待到期后再核一次名单，仍没有才判"这一次没等到"。
- **"该开新页却没等到"要记一笔**：per-call 记录里新增一个布尔键 `expected_new_tab_unfulfilled`，值挂在会话属性上（不放进 `_handle_click` 的返回字典，绝不进模型可见内容），**每次点击开始先复位**，也**不算失败**。
- **把跟随义务收窄成"界内注册"并写进规范**：用 `## MODIFIED Requirements` 整块改写既有条文 `Stay-hidden default and follow-new-tab (design 甲)` —— 界内注册的新页必须跟随；界由点击前的预检决定；**计时从点击返回之后起算**；界外才注册的页不跟随（这条如实写进规范，不再留一句做不到的无条件承诺）。同时把主规范里"per-call 记录包含哪些字段"那条要求也改写，把这个新键列进去、并写明它只描述这一次调用。
- **补一条确定性复现用例**：页面由**本地 HTTP 服务**提供（Chromium 不会把新标签页导航到 `data:` URL），链接 `target="_blank"` + 点击处理器 `preventDefault()` + `setTimeout(() => window.open('/landing'), 1500)` —— 新标签页**必然晚于 1 秒窗口、早于 5 秒窗口**。这条用例在现在的代码上稳定失败，修好后稳定通过。另补三条用例：既有那条同步弹窗用例加"命令总耗时小于 3 秒"的断言、普通原地点击不多等、具名目标也走长界、记录键在下一次点击里必须是 `false`。
- **同步用户文档**：`Docs/user-guide/tools-browser.md` 现在写着"每次点击最多等 1 秒"，改完就错了，同一个变更里改掉（CLAUDE.md 的硬性同步规则）。

### Modified Capabilities

- `browser-tool`：**改写**既有条文 `Stay-hidden default and follow-new-tab (design 甲)`（连同它的场景）—— 把"必须跟随新开的页"限定为"在该次点击的等待界内注册的新页必须跟随"，界由点击前的预检决定（`target="_blank"` 一类用较长的界，其余用现在的界），写明两个界都是上界、计时从点击返回之后起算，并补上"界内没等到时要记录、但不算失败"与"预检失败不得让点击失败"；另**改写**既有条文 `Text snapshot for a non-multimodal model` 里"per-call 记录包含哪些字段"这一句，把新键列进去并写明它是每次调用独立判定、不得进模型可见内容。

## Impact

- **产品代码**：`scripts/browser_worker.py` —— 点击前的预检、两个窗口（含起算点改到点击返回之后）、取页三步（页面处理器同时登记页对象）、per-call 记录新增一个键并每次复位。
- **测试**：`test/integration/browser_worker_test.dart` 新增"新标签页比 1 秒窗口更晚"的确定性用例、具名目标用例、记账键与其复位用例；既有那条"点 `target=_blank` 要跟随"的用例保留并加一条"命令总耗时小于 3 秒"的断言；重写 `_handle_click` 时**必须保留**既有源码扫描用例钉住的 `_recheck_window_bounds("click")` 调用点。
- **文档**：`Docs/user-guide/tools-browser.md` 的等待时长表述随代码同步（两处措辞不同，判据要按点名式核对）。
- **规范**：`openspec/specs/browser-tool/spec.md` 的两条既有条文（`Stay-hidden default and follow-new-tab (design 甲)`、`Text snapshot for a non-multimodal model`）经 `## MODIFIED Requirements` 整块合并；既有条文的改前/改后原文抄在 `tasks.md` 的收口条目里留档。
- **不做**（明确划界）：不动 `ctest` 里那条联网搜索用例的不稳定（另一件事）；不改"看不到窗口/最小化"相关行为；不改多标签页管理方式；不新增任何对模型可见的字段；**不给"锚点没有 `target`、由 JS 开页且晚于窗口"这一类加支持**（现状如此，本变更只是把它如实写进规范）。
- **兼容性**：只影响"点击后等多久再下结论"与"这一次点击怎么找到新页"；普通点击（无 `target`）的等待窗口不变；worker 与 sidecar 之间的报文格式不变；模型可见的返回内容一个字段都不加。
