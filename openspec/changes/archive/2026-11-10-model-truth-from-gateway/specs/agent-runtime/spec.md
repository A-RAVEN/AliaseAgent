# agent-runtime 能力（delta）

## MODIFIED Requirements

### Requirement: 每个 Agent 使用不可变的实例生效配置

系统 SHALL 在创建 Agent 时由模板与 Provider 目录解析出生效配置。**不可变（创建时解析、运行中不热更新）的范围**：provider 引用、模型、系统提示词、工具清单、上下文窗口、压缩参数、图片输入模态、命令超时与不可压缩要求——这些 SHALL NOT 因模板或目录随后变化而对已运行实例热更新。**例外：推理模式与强度**——`thinking_effort` SHALL 在每轮装配时按最新模板与目录重新解析（显式档位 > 目录中间档推导 > `disabled`，见 `agent-config` 的「缺省思考强度的推导」），模板修改从**下一轮装配**起对运行实例生效（在途轮的后续请求仍用旧档）。

上下文窗口 SHALL 按 `agent-config` 的「生效上下文窗口的解析顺序」在创建时解析：目录有正数 `context_window` 一律以目录为准，目录缺失时用配置正整数覆盖，两者皆无 SHALL 显示模板名并**拒绝创建**（不得按 0 继续、静默关闭压缩、整段发送或回落任何写死的窗口数字）。压缩阈值 SHALL 继续由窗口乘百分比推导。provider 密钥 SHALL 仅作为创建时的私有执行依赖使用，SHALL NOT 出现在实例生效配置的可序列化快照、模板菜单或日志中；真实创建与发送路径的日志断言 SHALL 能检出密钥泄漏。

#### Scenario: 双缺窗口拒绝创建

- **WHEN** 一个模板的模型目录无可用窗口值且配置没有合法 `max_context_tokens` 覆盖
- **THEN** 创建失败并显示该模板名，错误消息给出两条出路（探测目录 / 写覆盖值），不得回落任何写死的窗口数字

#### Scenario: 两个实例使用不同配置

- **WHEN** 两个 Agent 分别由不同模板创建，模板的模型与推理强度不同
- **THEN** 两个实例各自发送的模型请求使用各自的模型与推理配置，互不覆盖

#### Scenario: 推理强度修改下一轮装配生效

- **WHEN** 一个 Agent 已创建，随后其来源模板的 `thinking_effort` 被修改并保存
- **THEN** 该 Agent 从下一轮装配起使用新档，在途轮仍用旧档；同模板下新建/恢复的实例直接使用新值

#### Scenario: 其它字段修改仍不热更新

- **WHEN** 一个 Agent 已创建，随后其来源模板的模型、工具清单或窗口被修改并保存（窗口修改只影响目录缺失时的覆盖值）
- **THEN** 该 Agent 后续执行仍使用创建时的生效配置，之后新建或恢复的实例才使用修改后的模板

#### Scenario: 密钥不进入快照

- **WHEN** 一个 Agent 已解析 provider 并生成实例配置或上下文快照
- **THEN** 快照、模板菜单和日志不包含 provider 的 `api_key`
