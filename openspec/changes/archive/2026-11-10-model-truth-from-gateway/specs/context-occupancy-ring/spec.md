# context-occupancy-ring 能力（delta）

## MODIFIED Requirements

### Requirement: 环的几何

圆环 SHALL 以产生本次 `ContextSnapshot` 的 Agent 的实例生效配置中的模型上下文窗口为整圈——该窗口是创建时按 `agent-config` 的「生效上下文窗口的解析顺序」解析的结果（目录有正数 `context_window` 以目录为准，目录缺失用配置覆盖，双缺拒绝创建），不得在绘制时重新读取可能已被修改的 `agent_types.<名字>.max_context_tokens`，也不得随 Provider 目录刷新而改变已创建实例的环分母；每一段扫过的角度 SHALL 等于该段 token 数 ÷ 该实例窗口 × 360°；三段 SHALL 首尾相接、不重叠、不留空隙；绘制起点 SHALL 在 12 点方向，顺时针依次为 二级摘要 → 一级摘要 → 原文。模板窗口或目录后续修改 SHALL NOT 改变已创建实例的环分母。

**三段量的是什么（2026-10-18 定稿）**：量的是**这一次实际发出去那份请求**里对话消息那部分的构成（**不含**系统提示词与工具定义 —— 那两项不在环上），三段之和 ÷ 窗口就是环旁那个占比。
因此这个占比 SHALL **不可能超过 100%** —— 请求本身装不进窗口时压缩会先处理，能发出去就说明它装得下。

#### Scenario: 三段之和等于占用比例

- **WHEN** 三段 token 数分别为 a、b、c，当前 Agent 的实例窗口为 w
- **THEN** 三段扫过的角度之和 SHALL 等于 (a + b + c) ÷ w × 360°

#### Scenario: 模板改窗口不换旧实例分母

- **WHEN** 一个 Agent 已捕获上下文快照，随后其来源模板的窗口覆盖值被改小、或目录窗口值变化
- **THEN** 该 Agent 的环仍使用创建时解析出的窗口，不重算，也不会因此出现超过 100% 的显示

（其余场景——三段颜色、轨道跟随主题——不变，沿用主 spec。）
