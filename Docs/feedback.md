# 用户反馈记录

## F-001 粘贴网址弹"剪贴板里没有图片"

- **日期**：2026-11-11
- **对象**：产品（AliasAgent）
- **反馈原话**：「我往对话框里黏贴网址，却弹了"剪贴板里没有图片"」
- **场景**：在聊天输入框执行粘贴（Ctrl+V / 右键粘贴），剪贴板内容是**文本网址**，应用弹出提示"剪贴板里没有图片"。
- **期望**：粘贴文本就正常把文本放进输入框；只有粘贴图片意图（或剪贴板里真的是图片）时才走图片粘贴路径，且图片路径失败时才提示图片相关问题。
- **初步根因方向**（未核实，待查）：输入框的粘贴处理被"剪贴板图片"分支接管——粘贴事件进来先查剪贴板有没有图片，没有就直接弹了"没有图片"，而没有回退到默认的文本粘贴行为。需要查 `lib/main.dart` 输入框的粘贴拦截（`PasteTextIntent`/clipboard 监听/键盘粘贴钩子）与图片粘贴功能（`input_modalities` 相关附件路径）的先后关系。
- **状态**：待查（未立项）。确认根因后转 known-bugs 并开 change 修。

## F-002 工具调用与思考气泡默认折叠且折叠态只占一行

- **日期**：2026-11-11
- **对象**：产品（AliasAgent）
- **反馈原话**：「现在agent的工具调用和思考会导致大量气泡框，我希望工具调用和思考默认保持折叠状态，而且折叠状态要求只占一行，我看很多气泡框折叠了也占好几行，很丑」
- **场景**：对话里工具调用卡片（ToolCallCard）与思考（thinking）卡片连续出现时，消息区被大量气泡撑满；部分卡片即使处于折叠态也占多行高度，视觉拥挤。
- **期望**：① 工具调用与思考卡片**默认折叠**；② 折叠态严格只占**一行**高度（当前折叠后仍占多行的卡片要改成单行截断样式）。
- **状态**：已并入 `web-chat-screen`（2026-11-16 用户拍板并入新 web 界面，见 `TODO.md`「GUI web 化」节；同一 change 还含 2026-11-21 拍板的空气泡修复与自动重连）。web 客户端的工具/思考卡已默认折叠且折叠态严格单行。

## F-003 已在底部时新消息不自动滚到底

- **日期**：2026-11-11
- **对象**：产品（AliasAgent）
- **反馈原话**：「现在对话里面有时候即使拖到底了，新对话也不会让页面自动拖到最底」
- **场景**：用户已把消息列表滚到最底部，新消息（模型回复/工具卡片）到达后页面没有跟随滚动，需要手动再拖。
- **期望**：处于底部时新内容到达应自动滚到底（"贴底跟随"语义）；用户上翻阅读历史时则不打扰。
- **状态**：已并入 `web-chat-screen`（2026-11-16 用户拍板，见 `TODO.md`「GUI web 化」节）。web 客户端消息列表已按 bottomThreshold 贴底跟随，上翻不打扰。

- **日期**：2026-11-11
- **对象**：产品（AliasAgent）
- **反馈原话**：「另外还缺一个一键拖到最底的按钮，你类似于DSH的这个按钮」（附截图：DSH 输入框上方悬浮的圆形 chevron-down 按钮，带未读标记）

## F-005 别拿助手自造的承诺/约束来要求用户拍板

- **日期**：2026-11-22
- **对象**：助手（DSH 会话）
- **反馈原话**：「你为啥要用你自己的承诺来打扰我，你自己瞎做承诺为啥要我来拍板」
- **场景**：web-chat-screen propose 时，助手自己在 proposal 写了「本 change 不改核心 Dart 行为」的框框；对抗审查发现聊天屏必须 additive 扩 message.query 接口（正常实现所需），助手却把这个**自造约束**当成需要用户批准打破的「承诺」，反复请用户「拍板 P7」。用户从未提过「不改核心」要求。
- **期望**：实现用户需求所需的正常技术工作（含必要的接口增量扩展）直接做，不要先自造一个约束/承诺、再拿它去打扰用户拍板。用户拍板只用于真实的需求/方向取舍，不用于助手自己发明的框框。技术选型默认值按常理与产品先例定、文档化即可。
- **状态**：已纠正——撤掉工件里「不改核心承诺/待用户确认 P7/拍板门」等假框框，message.query 扩展按正常实现走。
