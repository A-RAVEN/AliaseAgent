# RoadMap

> 这份文件只讲**顺序与理由**：先做什么、为什么是这个顺序、哪一步是哪一步的前提。
> **可以勾选的待办条目只有一份，在根目录 `TODO.md`** —— 这里不复制清单，避免两处真相打架。
> 每个阶段做完，回来改本节的状态行，并在 `TODO.md` 里勾掉对应条目。

## 一、判断依据（为什么是这个顺序）

1. **先修"看得见内容不全会丢"的问题**。工具输出只留尾部会丢掉构建的第一条错误 —— 这是每天都会踩的痛，而且修法明确、不牵动架构。
2. **再修"状态是全局的"问题**。今天 sidecar 的工作区根、结果缓冲、浏览器 worker 都是进程级单例，因此**任何并发都不可能安全**。不先把它们变成"每 agent 一份上下文"，后面谈并行、谈子 agent、谈多 agent 都是空话。
3. **先完善 Agent 概念与基础配置**。上下文句柄只隔离执行状态，不等于 Agent 实体；先让每个 Agent 可指定模型、推理强度、系统提示词、工具集合与工作区，并拥有独立消息历史、模型—工具循环和生命周期，再谈子 agent。
4. **子 agent 只是 Agent 的创建接口**。主 Agent 与子 Agent 共用创建、配置校验、注册、取消与销毁设施；`spawn_subagent` 只是父 Agent 创建另一个 Agent、分配任务并取回结论。只读工具并行是独立的效率优化，可按需提前单独立项。
5. **多 agent 消息放在一次性子 agent 之后**。子 agent 在同一个 Flutter 进程内开新上下文、保持独立消息历史并复用现有模型—工具循环，只回传结论；等出现多个长期运行 agent 的真实协作场景再做异步消息，群聊暂不排阶段。
6. **进程隔离是"等崩怕了再做"**。它真正的收益是崩溃隔离（今天 C++ 一崩整个 App 跟着死），代价是流式回调要改成跨进程帧协议。前提是第 2 步的句柄化 API 先落地。
7. **模型元数据要有实测来源，不能手填**。Agent 已可按配置"用哪个模型"运行（阶段 3），但模型的上下文窗口与输入模态仍是每个模板手打的字符串，没有校验出处：本机实测手填窗口 1000000，网关目录真实值 1048576（差 48576 token，直接决定压缩阈值 250000 还是 262144）。用户已明确今后使用 magpie 网关（`yetone/magpie`，本机 127.0.0.1:3425 实测一个网关下 10 个模型、3 个上游），所以 **Provider 登记与模型探测插在效率优化（只读工具并行）之前**——窗口填错影响的是压缩正确性，并行快慢影响的只是等待。

## 二、阶段

### 阶段 1 —— 工具输出的交付契约（已完成，2026-10-25 归档）

- **change**：`openspec/changes/archive/2026-10-25-spill-large-tool-output`（36/36 任务；已归档，主规范 53 → 54 份）
- **状态**：已实现、已同步规范、已归档、已提交（`fbc4cef`）
- **做完的标志（实测，两条都成立）**：① 一条**真的失败**的 C++ 构建里，头部第 2 行的 `error C2065: "undeclared_symbol_at_line_1"` 出现在结果里；② `read_spill(offset=1018, limit=2000)` 读回的 2000 字节与 spill 文件对应区间逐字节相同（`integration_test/live_spill_output_test.dart`）
- **为什么第一个**：修法明确、不牵动架构，且它先把"输出怎么交付"这套契约定下来，后面子 agent 回传结果时可以直接复用
- **本期没做**：`web_fetch` / `grep_file` / `read_file` 的迁移（design D7 明确划到本期外）——~~`web_fetch` 的 2000 字硬切仍是缺陷，作为一条待办记在 `TODO.md`~~ **已完成**：`web_fetch` 于 2026-11-08 迁入 spill 通道（提交 `91e7512`），`grep_file`/`read_file` 本就只留必要摘要，不再迁。

### 阶段 2 —— 上下文句柄化（已完成，2026-11-01 归档）

- **change**：`openspec/changes/archive/2026-11-01-add-context-handles`（28/28 任务；已归档，主规范 54 → 55 份）
- **状态**：已实现、已同步规范、已归档、已提交（`778b933`）
- **做什么**：`sidecar` 增加 `create_context` / `dispose_context`；`g_workspace`、结果缓冲、浏览器 worker 全部变成"每上下文一份"；其余导出函数首参改成句柄。**Dart 侧要按会话/agent 建销句柄**，`sendMessage` 的串行化也按上下文分（现在是一条全局 `_chain`，只包模型请求，不包工具）。
- **本阶段必须覆盖的全局状态（2026-10-25 补全）**：
  - `sidecar/src/tools.cpp` 的 `static std::string g_workspace`；
  - `sidecar/src/sidecar_api.cpp` 的 `static std::string g_*_result`（含 `g_last_tool_result` 与 `g_read_spill_result` —— 后者是 spill 这次新引入的）；
  - `sidecar/src/browser.cpp` 的唯一 worker：要变成"每上下文一个 worker"或"每上下文一个浏览器会话"，不是只挪缓冲；
  - `sidecar/src/spill.cpp` 的 `static unsigned g_call_seq`（`++g_call_seq` 非原子：**同一会话内**并发调用会撞序号写同一文件；跨会话因目录不同不撞）。
- **做完的标志**：① 两个上下文同时存在且互不干扰（一个设工作区、另一个调工具，结果不串）；② 同一会话内并发跑 `run_command` / `read_spill` 时结果与 spill 文件都不串、序号不撞；③ 两个会话能各自发模型请求，不再被一条全局 `_chain` 排队。
- **为什么第二个**：它是并发、子 agent、进程隔离三件事共同的前置。跳过它，后面每一步都要先绕开全局状态。
- **一个常见误解**：这一步**不是**给"开两个 session"做内容隔离 —— 消息本来就按 `session_id` 存在 SQLite 里（`queryBySession` 用 `where: 'session_id = ?'`），模型上下文在 Dart 侧按会话拼装。它要解决的是**工具执行时的全局状态在并发下被覆盖**。

### 阶段 7 —— 多 agent 异步消息（候选，看需要）

- **做什么**：为多个长期运行的 agent 传递异步消息。一次性子 agent 只走"任务 → 结论"的回传，不需要这套消息机制；群聊暂不另列阶段
- **什么时候立项**：出现多个长期运行 agent 的真实协作场景，再把消息投递、恢复与调度写成能失败的验收
- **为什么在这里**：它是子 agent 之后的协作增强，不是 Agent 对象化、子 agent、只读工具并行或进程隔离的前置

### 阶段 8 —— 进程即 agent（未立项，长期）

- **做什么**：把上下文塞进独立进程，句柄改成"进程 + 会话 id"，用仓库里 `browser.cpp` 已有的 stdin/stdout JSON 帧协议
- **做完的标志**：故意让 sidecar 段错误，App 只报"这个 agent 挂了"，界面与其它会话不受影响
- **为什么不急**：它的主要收益是崩溃隔离；流式回调改成跨进程协议是整块工作量

### 阶段 9 —— 符号索引（未立项，看需要）

- **做什么**：给"找代码"提供定义/调用/所在文件的结构化查询，替代纯文本 grep 试错
- **为什么最后**：只在大仓库里才痛；而且有了阶段 4 的子 agent 之后，"翻代码"的 token 压力已经小很多

## 三、独立能力候选（不阻塞上述主线）

系统提示词分层、技能、斜杠命令与 MCP 是彼此独立的能力候选，不是句柄化、子 agent 或多 agent 消息的前置。具体待办见 `TODO.md`；确定要做时分别单独立项。CLI 与群聊目前不列待办、不排阶段。

- **技能（已定方向，2026-11-06 用户拍板）**：加载技能全文由一个专门工具承担——不给 `read_file` 开工作区边界例外，也不把技能文件放进工作区来绕开工具；首版只做全局安装的技能目录，不做工作区一级的技能。目录注入与按需加载在 `TODO.md` 对应条目。
- **落地状态（2026-11-11）**：技能机制、每轮热刷新、创建简则、斜杠触发均已归档（`add-skill-mechanism` / `refresh-skill-catalog-each-turn` / `add-slash-commands`）；技能名 Tab 补全已实现并归档（`slash-command-completion`，2026-11-12，提交 `3e5ec1c`）。

- **GUI 改造（2026-11-16 用户拍板：直接 web 化，路线 A 取消）**：背景——同类项目（DSH=纯 web、Magpie=Wails v3+WebView2、Cherry Studio/Chatbox/Jan/Claude Desktop=Electron/Tauri）几乎清一色 web 技术栈，图的是 Markdown/流式渲染生态与现成设计组件；AliasAgent 的 Flutter 自绘路线缺少可抄作业，观感债在累积（反馈台账 F-002 卡片折叠、F-003/004 滚动，均记于 `Docs/feedback.md`）。**路线 C（唯一路线）：UI 层 web 化**——Dart 业务层（Agent/压缩/技能/spill/配置/DB，全部 live 实测资产）抽成无头进程加 WebSocket/JSON-RPC shim，C++ sidecar 仍由该进程 FFI 加载，界面用 web 技术栈重写（Tauri 壳或直接内嵌浏览器窗口）；周级战略工程、独立多 change 项目、逐屏灰度迁移；架构先例=DSH（核心+web GUI）。**F-002~F-004 并入 C 的新界面需求，不在旧 Flutter 界面修**（2026-11-16 用户选定）。历史：2026-11-11 explore 曾定「A（Flutter 内立设计系统）先、C 后」，2026-11-16 用户反转——原话「既然web化是目标，就没有A的必要吧」，A 不再单独立项。
- **阶段顺序（2026-11-18 登记，2026-11-22 更新，条目在 `TODO.md` 的 GUI web 化节）**：① `web-ui-core-shim`（无头核心 + RPC + 静态服务 + 最小验证页）——先做，因为它把「无头核心能否复用全部业务 / RPC 通道 / web 渲染」这条架构先验证掉，后续屏才敢往上堆；② 完整聊天屏 change（F-002~F-004、虚拟滚动、分页落地）——必须在 ① 之后，屏幕要复用已验证的通道与事件契约；③ `agent-group-chat`（群聊/聊天组：单一共享原文 + 逐成员视图投影 + 逐视图压缩 + 成员定制覆盖层）——排在聊天屏与管理界面之后，复用已验证的通道/事件契约/管理屏；**规模优化（`Agent.restore`/`_history` 内存边界）并入 ③ 当前置任务**——N 成员视图才是内存压力的真实触发器，用真实群跑测出压力再定边界（原「排在完整屏之后」的理由在此落地）；④ 核心 Dart→TS 迁移 change（终态 C++ + TS）——最后，等界面与 RPC 契约稳定后再迁；C++ sidecar 恒留。**进度（2026-11-22）**：① 已归档（`fd9f340`）；② 已归档（`2f57b43`）；② 与 ③ 之间插入的管理界面 change `web-management-ui`（会话管理/图片+占用环/provider/模板/首启向导，2026-11-22 用户拍板三阶段合一）已归档（`f396feb`）——web 端可独立完成首启与全部管理；③ `agent-group-chat` 已归档（2026-11-22，66/66 + 主循环复核：全量 +1039、四变异红证据、真核心视觉 design_audit 0/86、live 真模型隐私隔离；用户拍板群聊方向：共享对话记录作公开上下文、各成员工具/思考仅自己与用户可见、单一原文 + 可见性剔除 + 主客体解析的视图口径、逐成员视图为压缩对象）——自动编排（@mention/主持人/并行）留待后续；④ 未开始。 spawn_subagent 保持一次性委托形态不变，群聊是其持久化对等泛化，两形态并存。

## 四、明确不做

| 不做 | 原因 |
|---|---|
| 文件快照 + 一键回退 | 用户否决：只是 git 的补充、用得少、静默回退会让模型上下文变成假的（台账第 24 条） |
| 命令审批 / 沙箱 / 危险命令拦截 | 用户否决：明确要零审批的全权限运行（台账第 25 条，`CLAUDE.md` 已写成立场） |
| 向量检索 / RAG | 这个项目里"找代码"靠名字与结构就够，语义相似度是次要的；符号索引更划算 |
