# 子 Agent（spawn_subagent）

## 这是什么

`spawn_subagent` 是一个工具。父 Agent 可以让一个**一次性子 Agent**去完成一件范围明确的任务，然后只拿到它的**最终结论**。

为什么要有它：大范围调查（读很多文件、试很多命令）如果都塞进主对话，主对话会被中间过程占满。交给子 Agent 之后，中间消息、思考与工具输出都留在子 Agent 自己的历史里，主对话只增加一条工具调用和一段结论。

它不是"另一个聊天窗口"：子 Agent 跑完就结束，不能继续对话，也不会出现在侧栏。

## 在哪用

这不是一个需要你点按钮的功能。它由**模型**在需要时调用，前提是两个条件同时成立：

1. 当前会话的模板勾选了 `spawn_subagent`；
2. 工具的输入合法（任务非空，模板名存在）。

### 怎么给模板勾上

1. 点会话侧栏的 `Agents`。
2. 点目标模板右侧的铅笔按钮（提示文字：`修改模板`）。
3. 在工具勾选区勾上 `spawn_subagent`。
4. 点 `保存`。

保存只影响**之后创建或恢复**的实例；已经运行中的会话要继续用它，需要重启应用，或用工具栏的模板下拉切换一次。

反过来，取消勾选并保存即可移除。**从当前十一项基础工具里删掉 `spawn_subagent` 后，重新加载不会自动加回来**——旧版的十项默认清单和"你自己删掉了它"在配置文件里长得一模一样，应用无法区分，所以不会替你改。

## 模型要填什么

工具输入是两部分：

| 参数 | 必填 | 说明 |
|---|---|---|
| `task` | 是 | 给子 Agent 的完整任务。子 Agent **看不到父对话**，背景、文件路径、验收标准都要写在任务里；空字符串或纯空白会被拒绝（`invalid_task`） |
| `agent_type` | 否 | 子 Agent 使用的模板名。省略时**继承父 Agent 的模板**（不是固定 `general`）；写不存在的模板会被拒绝（`invalid_agent_type`），不会退回 `general` |

## 它会怎么跑

- **同步等待**：父 Agent 会等子 Agent 整轮结束（模型循环、工具、写库）才拿到结果。等待期间主对话的工具卡片显示 `Executing...`；同一时间不会并行跑多个子 Agent。
- **独立历史**：子 Agent 有自己的上下文句柄、消息历史、配置快照、取消状态与计量。它不复制父对话消息，父对话也不会出现它的中间消息、思考或工具输出。
- **工作区继承**：子 Agent 继承**父上下文在调用那一刻实际保存的工作区**，不是应用主目录，也不是界面当前选中的别的会话。父子之后各用自己的上下文句柄执行工具。
- **只看结论**：父 Agent 只收到子 Agent 的最终回复。子 Agent 的 token 与请求数单独计量，不加进父 Agent 的计量。
- **不能嵌套**：子 Agent 的实际工具清单里排除了 `spawn_subagent`，所以它不能再创建下一层；父 Agent 自己的工具清单不受影响。
- **任务卡片**：主对话里出现一张工具卡片，标题显示子 Agent 模板，正文显示任务；结束时显示结论（点 `Expand result` 看完整结论），失败时显示错误。

## 结果与错误

成功时工具结果只有子 Agent 的最终结论。子运行的诊断信息（子会话 id、实际模板、模型、子计量）写在工具卡片对应的持久化记录里，供排查使用，不进入模型可见的结论正文。

失败时工具结果以 `ok:false` 返回，父 Agent 会看到可区分的错误。常见几类：

| 父模型看到的 | 意思 |
|---|---|
| `invalid_task: ...` | 任务为空、纯空白或不是字符串；没有创建任何子运行 |
| `invalid_agent_type: ...` | 指定的模板不存在、provider 未定义、窗口非法或含未知工具；没有创建子运行 |
| `workspace_unavailable: ...` | 读不到父上下文的工作区；没有创建子运行 |
| `child_session_failed: ...` / `child_create_failed: ...` | 子会话记录或子实例没建起来；不会留下半个运行 |
| `subagent_failed: ...` | 子 Agent 的模型请求失败 |
| `subagent_cancelled: ...` | 子 Agent 被取消（父取消、父销毁等） |
| `empty_final_response: ...` | 子 Agent 跑完了但没有最终文本；不把空内容当成功结论 |
| `subagent_busy: ...` | 子实例正忙，这次调用没有开始 |
| `subagent_exception: ...` | 子 Agent 运行中抛出了未预期异常 |
| `cleanup_failed: ...` | 子 Agent 结束但上下文没能证明排空；资源可能仍在，不谎报"已释放" |

## 取消与清理

- **单独取消子运行**：只取消这个子 Agent，父 Agent 收到取消错误后可以继续自己的循环。
- **父取消 / 父销毁**：先取消正在运行的子 Agent，再取消父请求；等子整轮与清理结束，父的销毁才完成。
- **模板切换**：父 Agent 的退役**不会**取消在途子调用；子调用与父整轮自然结束后旧实例才让位。
- 子 Agent 结束后，应用会销毁它的上下文（浏览器会话、spill 目录等）并从运行实例表移除；**子会话的数据库记录保留**，但普通会话列表与启动恢复都不会碰它们。

## 子 Agent 的 spill 引用不能当交付物

子 Agent 的长输出也会落进它自己的 spill 目录。这些文件在子 Agent 结束时随上下文销毁，**它给出的 `read_spill` 引用随后就失效**。

所以：

- 子 Agent 的最终回复必须自包含（任务说明与它的角色说明都要求这一点）；
- 需要持续保留的内容，应让子 Agent 写进继承的工作区文件；
- 父 Agent 不要指望子 Agent 的 spill 引用在之后还能读。

## 限制

- 第一版**不能嵌套**：子 Agent 不能再创建子 Agent。
- 第一版**没有并行**：一次只有一个同步调用，也没有异步消息或后台驻留。
- 子运行记录**不在侧栏**，也**没有详情界面**；它们只保留在数据库里供诊断。
- 子 Agent 与父 Agent 的计量各自独立，不会合并。
- 最终结论不做长度截断：很长的结论仍会占用父对话上下文（这是有意为之，避免静默少给）。
- 子 Agent 看不到父对话：任务写得不够自包含时，它只能就事论事地做完你写下的那部分。
