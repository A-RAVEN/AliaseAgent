# Provider 与模型目录

## 这是什么

一个 **Provider** 就是一把密钥 + 一个网关地址。AliasAgent 可以用多个 Provider（比如一个官方 API、一个本机 magpie 网关），模板里选哪个 Provider，就用它的地址和密钥发请求。

每个 Provider 还可以保存一份**模型目录**：点一次探测，应用向网关请求模型清单，把每个模型的上下文窗口、输入模态、推理档位等元数据记进 `~/.aliasagent/config.json`。模板编辑器的模型下拉与回填默认值就来自这份目录。

目录只是**配置快照**：模板里存的显式值仍是唯一执行真相，刷新目录不会回改已经保存的模板。

## 在哪用

会话侧栏 `New Chat` 下面有两个入口：`Agents`（模板）和 `Providers`（供应商）。

界面文案：`Providers`

点开后是 Provider 列表，每一行显示：

- 名字；
- 网关地址（存储前已归一化：尾部的 `/` 与 `/v1` 会剥掉，所以你填 `http://127.0.0.1:3425/v1` 显示成 `http://127.0.0.1:3425`）；
- 目录状态：`目录 N 条 · 取自 <探测时刻>`，从没探测过时显示"未探测"；
- 本次运行里最近一次探测的结果（成功是四类计数，失败是原因）。

界面文案：`未探测`

## 怎么操作

### 添加 Provider

1. 点列表底部的 `添加 Provider`。
2. 填 Provider 名称、网关地址、API Key。
3. 点 `保存`。

第一次启动的向导会预填 magpie 的默认三件套：名字 `magpie`、地址 `http://127.0.0.1:3425`、密钥 `magpie`（都可以改）。这里手动新增时没有预填，按你的网关填写。

保存成功后会**自动探测一次**（网关不可达时只是那一行显示失败，配置已经保存，不回滚）。密钥输入框是遮蔽的；列表里不会显示密钥明文。编辑时密钥留空表示"沿用原密钥"。

### 编辑 / 改名

点某一行的铅笔按钮改地址、密钥或名字。改名会在**同一次写回**里把所有引用旧名的模板的 `provider` 字段改成新名，不会留下悬空引用。

### 删除

点某一行的删除按钮。若仍有模板引用这个 Provider，删除会被拒绝，那一行会列出引用它的模板名（例如"被 general 引用，不能删除"）。没有被引用时立即删除并写回配置。

### 探测

每一行有 `探测` 按钮；新增、改名、改地址、改密钥保存成功后也会自动探测一次。

探测结果的四类计数：

| 计数 | 含义 |
|---|---|
| 新增 N | 本次目录里有、旧目录里没有的模型数 |
| 更新 M | 两边都有、但元数据（窗口 / 模态 / 档位等）有变化的模型数 |
| 移除 K | 旧目录里有、本次网关不再返回的模型数（网关下架） |
| 丢弃 X | 本次响应里缺字符串 id、被逐条丢弃的坏条目数 |

移除与丢弃是**两种相反的失败原因**：移除是网关下架，丢弃是解析失败，所以分开计数，丢弃绝不并入移除。探测失败时旧目录与探测时刻原样保留，不清空。

启动应用、切换会话、打开模板编辑器都**不会**发探测请求；除了上面两个时机（手动点探测、保存 Provider 后自动一次）没有别的触发，也没有定时器。

### 在模板里选模型

打开 `Agents` → 添加或修改模板。模型字段有两条路：

- 右边的目录下拉：显示网关给的 `display_name`，值是模型 id。切换 provider 后，下拉会换成那个 Provider 的目录。
- 左边直接手输模型名：目录可能陈旧或网关不支持探测，手输永远可用；输入的名字不在最近一次目录里时会显示中性提示"不在最近一次目录中"，**不会**阻断保存。

从目录选中一个模型后，编辑器会用目录值预填三个输入框：

| 输入框 | 回填规则 |
|---|---|
| 上下文窗口 | 取目录的 `context_window`。目录标"窗口未知"时留空，并提示"目录未提供窗口，请手填（压缩阈值依赖它）"——压缩阈值靠这个数推导，必须手填 |
| 输入模态 | 取目录的输入模态与 text / image 的交集。网关能收 video 不代表产品会发 video，目录原值仍保留在配置文件里，但模板只勾 text / image，界面上会说明哪一项被略去 |
| 推理强度 | 下拉选项 = 目录档位与执行层合法集合的交集；目录里的 none 映射为"关闭"（留空 = 不思考）；执行层不支持的目录档位不会静默消失，界面会显示"目录档位 X 暂不被执行层支持，未列入" |

预填只是默认值：你可以改，保存后以你填的为准。目录里的 `native_endpoints` 与 `pricing` 只在选中模型后显示为参考说明，**不**作为"这个模型能不能用"的门禁（网关文档原文：该字段只标哪些协议路径原生直通，缺它不代表不能发 Messages 请求）。

目录为空、Provider 没有目录、或者目录里没有这个模型时，窗口、模态、推理强度全部照旧手填。一个 Provider 都没有时，模板编辑器显示"请先在 Providers 页添加供应商"并禁用保存按钮。

界面文案：`请先在 Providers 页添加供应商`

界面文案：`目录未提供窗口，请手填（压缩阈值依赖它）`

## 探测失败会看到什么

探测失败显示在该 Provider 行内，格式是"探测失败：原因"，旧目录条数不变：

| 显示 | 原因 |
|---|---|
| 探测失败：HTTP 401 | 密钥不对或网关要求鉴权 |
| 探测失败：HTTP 404 | 网关没有 /v1/models 这个路由（不是 magpie 标准网关时常见） |
| 探测失败：连接失败：... | 网关进程没起、地址或端口不对 |
| 探测失败：连接或读取超时（连接 15 秒 / 读取 15 秒） | 网关可达但没在 15 秒内答完（与产品既有对外 HTTP 超时同值） |
| 探测失败：该端点不是 magpie 标准目录：共 N 字符，已略去 M 字符，完整内容见 <路径> | 返回的不是 `{"data":[...]}` 形状（网页、别的方言、错误 HTML）。预览按 `spill.preview_chars` 截取（缺省 1000，头尾各一半），完整原始响应不截断地写进 `~/.aliasagent/logs/model_discovery_error_<UTC 时刻>.txt`，按提示的路径能读到与网关返回逐字节相同的全文 |

密钥不会出现在错误信息或日志里。失败不弹确认框、不回滚已保存的配置。

## 已知限制

1. **只认 magpie 标准方言**：`GET /v1/models` 必须返回 `{"data":[...]}`。别的方言（例如 DeepSeek 的 Anthropic 兼容端点，实测返回 404）会被判"不是 magpie 标准目录"，旧目录保留，模型仍可手填。
2. **目录不自动刷新**：只有手动点"探测"或保存 Provider 时更新；应用启动与定时后台都不会探测。目录陈旧时看"取自 <时刻>"自行判断。
3. **video 收不了**：目录里记录的 video 等输入模态只作展示与记录，模板的输入模态仍只允许 text / image；目录刷新不会让产品发送它发不出的内容。
