# 联网工具

## 这是什么

三个工具：`web_search`（搜索）、`web_fetch`（抓一个网页的正文）、`get_current_time`（当前时间）。

**这三个都是模型自己调用的，你不需要（也无法）手动点它们。**

## 一个前提：搜索要花钱的服务

`web_search` 和 `web_fetch` **只有在你配置了至少一家搜索服务时才会出现**。配置里没写 `search` 这一块，模型就没有这两个工具可用（它当然也不会知道外面发生了什么）。

可配的服务（见 [配置](configuration.md)）：

| 服务 | 要什么 | 现在能不能用 |
|---|---|---|
| `zhipuai` | 付费 key（`api_key`） | 能用 |
| `kimi` | 付费 key（`api_key`） | 能用 |
| `searxng` | 自建服务地址（`base_url`） | **这一版用不了** —— 启动时会跳过它的连通性检查并直接当成不可用 |

`get_current_time` **不需要任何配置**，一直在。

## 在哪用

你只要在对话里正常提问。模型自己判断要不要搜、抓哪个链接。每次调用在对话里出现一张卡片，展开能看到搜索词、抓的网址和返回内容。

## 三个工具分别干什么

### `web_search` —— 搜索

| 参数 | 含义 |
|---|---|
| `query` | 搜索词（必填） |
| `providers` | 用哪几家服务；不填 = 全用 |
| `depth` | `basic` = 只要摘要（快）；`deep` = 抓全文（慢） |
| `max_results` | 最多几条，1 到 10，默认 5 |

返回结果会按服务分组；一条都没搜到时卡片上是 `No results found`，有结果时是 `<N> providers, <M> results`。

### `web_fetch` —— 抓一个网页

| 参数 | 含义 |
|---|---|
| `url` | 要抓的网址 |

返回的是**正文纯文本**（去掉了网页的导航、广告等结构）。搜索摘要不够时，模型会用它去读整篇文章。

### `get_current_time` —— 当前时间

没有参数。返回日期、时间、时区。系统提示词里已经告诉模型：**要精确时间就用这个工具**（模型的训练数据有截止日期，不问就不知道今天几号）。

## 出错时会看到什么

| 卡片上的结果 | 含义 | 怎么办 |
|---|---|---|
| `No search providers configured` | 一家搜索服务都没配 | 在配置里加 `zhipuai` 或 `kimi` 的 `api_key`，重启应用 |
| `Search query is empty` | 搜索词是空的（模型调用出错，很少见） | 重说一次你的问题 |
| `All providers failed: <服务名>: <原因>` | 搜索服务都不通：key 无效、欠费、超时、网络不通 | 按冒号后面的原因查；key 或余额问题要自己去服务商那边处理 |
| `Fetch failed: internal address not allowed` | 想抓的是本机或内网地址（例如 localhost、127.0.0.1、192.168.x.x） | 这是**故意拦的**（防止模型去读你本机上的服务）；要抓公网地址 |
| `Fetch failed: URL scheme not allowed` | 网址不是 http/https（例如 `file://`） | 换 http/https 地址 |
| 卡片状态 `Error` | 上面任何一种失败 | 展开卡片看具体文案 |

## 限制

- **联网要花钱**：搜索和抓取都要消耗搜索服务那边的额度。
- **抓不了内网和本机地址**：本机服务、路由器管理页面这类网址一律被拒。
- **搜索只走你配的服务**：没配就没有搜索工具；`searxng` 这一版用不了。
- **`web_fetch` 抓的是正文文本**，不是网页原样；需要看页面结构时它帮不上忙（那种场合用 [浏览器工具](tools-browser.md)）。
- **结果不一定准**：搜索和抓取的内容来自公网，模型会照抄其中的说法。
