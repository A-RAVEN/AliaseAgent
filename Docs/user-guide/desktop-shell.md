# Windows 桌面壳（双击启动 / 托盘常驻）

> 对应 change：`windows-desktop-shell`。壳是**过渡层**：它只负责「固定地址 + 起停核心 +
> 托盘」。核心与 web 客户端不受它影响，不启动壳时「手工起核心 + 浏览器」的用法照旧。

## 这是什么

`AliasAgent.Desktop.exe` 把原来三步（开终端 → 起无头核心 → 开浏览器）收成**一次双击**：

1. 壳解析仓库根与端口，做预检（`web/dist`、dart、仓库根）；
2. **先建托盘图标**（冷启动期间你就看得见它在跑），再起 Dart 无头核心子进程；
3. 等 `core.ping` 通，然后在自己的窗口（WebView2）里加载
   `http://127.0.0.1:<port>/`。

关窗口 **≠** 退出：关窗只是隐藏到右下角通知区域（托盘），核心继续常驻；只有托盘菜单
的「退出」才真的停核心并结束进程。

## 前置条件

| 什么时候要 | 要什么 | 缺了会怎样 |
|---|---|---|
| 构建壳 | .NET SDK（仓库根 `global.json` 钉住 `11.0.100`；用它构建 `net10.0-windows` 目标） | 构建脚本报「找不到 dotnet」并说明要装什么 |
| 构建壳（首次） | 网络（首次自包含发布要下载 net10 运行时包，上百 MB） | 脚本把失败归类成「网络 / 依赖源原因」，不是含糊的「构建失败」 |
| 运行壳 | WebView2 Evergreen 运行时（Windows 11 自带；本机实测 `pv=157.0.4341.60`） | 初始化失败 → **先停核心、放锁**，再弹「缺 WebView2 运行时」并退出 |
| 运行壳 | PATH 上的 dart（或用 `ALIASAGENT_DART` 指定；本机 `Get-Command dart` 指向 `E:\Flutter\flutter\bin\dart.bat`，壳会经 `cmd.exe /C` 启动它） | 预检失败并给出三种补法 |
| 运行壳 | `web/dist/index.html` | 预检失败，提示先 `cd web && npm install && npm run build` |

运行壳**不需要**另装 .NET 桌面运行时（自包含发布）。

## 怎么构建

从仓库根执行（脚本自己会切到仓库根，因为 dotnet 只从当前目录向上找 `global.json`）：

```powershell
powershell -NoProfile -File scripts\build_desktop_shell.ps1
```

脚本会：打印实际 SDK 版本并与 `global.json` 对照 → `dotnet publish`（Release / win-x64 /
自包含）→ 校验 `AliasAgent.Desktop.exe` 与 `WebView2Loader.dll` 都在 → 打印双击哪个文件。
任一关键步骤非零即中止（不产出半份）。

产物目录是 `shell/dist/`（已 gitignore，绝不入库）。双击这个文件启动：

```text
shell\dist\AliasAgent.Desktop.exe
```

## 怎么启动

双击即可。也可以带参数：

```text
AliasAgent.Desktop.exe [--config <path>] [--port <n>] [--repo-root <path>] [--selftest]
```

| 参数 | 作用 |
|---|---|
| `--config <path>` | 指定配置文件（默认 `%USERPROFILE%\.aliasagent\config.json`）。壳读它取端口，并把同一份显式传给核心 |
| `--port <n>` | 显式端口（1–65535）。**壳不接受 `--port 0`**：0 只用于核心侧调试/测试 |
| `--repo-root <path>` | 指定仓库根（默认从可执行文件目录向上找含 `pubspec.yaml` 与 `bin/alias_agent_core.dart` 的目录） |
| `--selftest` | 无窗口自检（见下） |

## 双击后看到什么

1. **通知区域先出现托盘图标**，提示「AliasAgent 正在启动核心」，右键菜单此时只有「退出」；
2. 冷却期（首次 `dart run` 要编译内核，实测见 change 报告的冷启动读数）里窗口还没出现，
   但你能看到托盘图标 —— 不会「双击了像没反应」；
3. `core.ping` 通之后窗口弹出（首次即最大化），里面是 web 聊天界面。

## 托盘怎么用

- **关窗口**：窗口消失、托盘图标还在、核心继续跑（此时访问固定端口仍返回 200）。
  第一次关窗会弹一次气泡说明「仍在后台运行」。
- **双击托盘图标**：窗口回来并获得焦点（不用重新起核心）。
- **右键托盘菜单**：
  - 「打开窗口」——同双击；
  - 「退出」——真正退出（见下）；
  - 「重启核心」——**只在核心崩溃后出现**（不自动重启，避免把崩溃原因掩盖成反复闪烁）。
    重启**失败**（端口仍被占 / 核心仍起不来 / 就绪前退出等）时壳**不会退出**：窗口显示
    「重启核心失败」错误页、托盘弹气泡、日志点名原因与日志路径，菜单里的「重启核心」仍然
    可用，修好原因后可以直接再点一次。

## 怎么真退出

托盘菜单点「退出」：壳先经 `core.shutdown` 礼停核心（上限 5000 毫秒），超时才终止核心
进程树；随后隐藏并释放托盘图标，进程以 0 退出。

极端异常（礼停与杀树**都**失败）时会先弹托盘气泡点名 pid 与「未能终止核心」，再释放图标退出
——这是异常兜底，不是正常路径。细节看日志
`%USERPROFILE%\.aliasagent\logs\desktop-shell.log`。

## 固定端口怎么改

端口按优先级决定：**`--port` > 配置 `core.port` > 默认 `16705`**。

```jsonc
// %USERPROFILE%\.aliasagent\config.json
{ "version": 1, "core": { "port": 9000 }, ... }
```

- 改 `core.port` 要重启壳（壳启动时读一次）。
- 配置项非法（字符串、0、负数、大于 65535）→ **回落默认值并留一行日志**，不拒绝启动。
- 端口被占用 → **显式失败**并点名端口与改法（改 `core.port` 或用 `--port` 指定另一个端口），
  **不会静默换端口**——固定端口的全部价值就是地址稳定。
- 低端口（`<1024`）：**只是容易与系统服务相撞、不推荐**。Windows 没有 Unix 式特权端口，
  非提权绑定低端口是可行的（不需要「管理员权限」）。
- 同一台机器多用户 / 多登录会话同时用：回环端口是**机器级**资源，壳的单实例互斥体只管
  当前登录会话；第二个会话会得到可归因的「端口被占」，其中一个要改 `core.port`。

## `--selftest`：无窗口自检

```powershell
shell\dist\AliasAgent.Desktop.exe --selftest
```

它验的是「起核心 → 就绪 → 静态页 → 停机 → 锁释放」整条链路，**不开窗、不建托盘图标**，
并且能与「你此刻正开着壳」并存：

- 不取壳的单实例互斥体（分流发生在取互斥体之前）；
- 用临时 `--config`、临时 `USERPROFILE`、临时 `--lock`，自检日志也写临时目录；
- 端口是**当场取的空闲端口**（绑 0 → 立刻释放 → 显式传给核心）。

每步打印 `[SELFTEST] <步骤> <结果>`，任一步失败就打印原因并以非零码退出。
**端口竞态**：从「释放端口」到「核心 bind」之间理论上可能被抢（TOCTOU），被抢时会得到
可归因的绑定失败——自检因此不是「保证成功」，也**不做换端口重试**（那会把真实占用掩盖成偶发）。

自检通过**不等于**窗口与托盘外观正确：外观只由视觉验收判定。

## 出错时会看到什么

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 对话框「启动失败：找不到仓库根」 | 从可执行文件目录向上找不到 `pubspec.yaml` + `bin/alias_agent_core.dart` | 用 `--repo-root <仓库根>` 指定 |
| 对话框「启动失败：环境不满足」+ 缺 web 产物 | `web/dist/index.html` 不存在 | `cd web && npm install && npm run build` |
| 对话框「启动失败：环境不满足」+ dart 不可解析 | `ALIASAGENT_DART` 没设、PATH 上也没有 dart | 装 Flutter SDK / 把 dart 放进 PATH / 用 `ALIASAGENT_DART` 指定 |
| 对话框「启动失败：核心在就绪前退出」 | 常见：已有核心在运行（单实例锁被占）、端口被占、配置损坏 | 对话框里有退出码、最后一行输出、日志路径；按提示处理后重试 |
| 对话框「启动失败：核心没有就绪」 | 核心活着但在 30000 毫秒内没回 `core.ping` | 看 `desktop-shell.log`；半死的核心会被停掉，不留占端口的进程 |
| 对话框「停 WebView2 初始化失败：缺 WebView2 运行时…」 | Windows 缺 Evergreen 运行时 | 装 WebView2 Evergreen 版；壳已经先停核心并放锁，不会留下孤儿核心 |
| 对话框「初始化 WebView2 失败：用户数据目录不可用（…）」 | `%LOCALAPPDATA%\AliasAgent\WebView2` 不可写 | 修权限或换目录后重试 |
| 窗口里「界面加载失败」错误页 | 导航失败（核心刚重启、web 产物不完整等） | 从托盘关掉窗口再打开可重试（会重新导航） |
| 气泡「AliasAgent 核心已退出」+ 菜单「重启核心」 | 核心非预期退出 | 看日志与退出码，点「重启核心」重试 |
| 气泡「AliasAgent 重启核心失败」+ 窗口「重启核心失败」错误页 | 重启时核心仍起不来（端口仍被占 / 配置仍损坏 / 就绪前退出） | 壳保持运行、菜单仍有「重启核心」；按错误页与日志修好原因后再点，或点「退出」 |
| 双击后直接退出、无窗口 | 已有另一个壳实例在跑（第二次双击会把「打开窗口」转给它） | 去托盘找已有窗口；这是单实例行为，不是失败 |

## 两把锁的区别

- **壳的单实例互斥体**（`Local\AliasAgent.Desktop.SingleInstance`）只管**壳**：挡双开壳、
  把第二次双击转成「打开窗口」。作用域是当前登录会话。
- **核心的单实例锁文件**（`~/.aliasagent/core.lock`）只管**核心**：挡双开核心。
  两者独立生效；壳发现核心锁被占用时会如实报「已有核心在运行」（它不会接管别人的核心，
  也不会在退出时停掉不是它启动的核心）。

## 已知限制

- **已知端口 + 无鉴权**：核心只绑 `127.0.0.1` 且**没有鉴权**。端口从「随机」变成「已知」后，
  本机恶意网页更容易命中它；而且 `core.shutdown` 允许**任何本机进程（含本机网页）关停核心**。
  这是本 change 明确接受并披露的取舍（要鉴权得另立 change）。
- **关窗是后台常驻**：关窗后进程还在、核心还在。要真退请用托盘「退出」，否则会出现
  「以为退了其实还在跑」的困惑（第一次关窗的气泡就是为这个）。
- **多用户同机撞端口**：同一台机器多个登录会话各自起壳时，`Local\` 互斥体互不冲突，但都会去
  绑同一个默认端口 → 第二个得到「端口被占」。给其中一个改 `core.port`。
- **没有日志轮转**：`desktop-shell.log` 只追加不轮转（体积会增长）。
- **托盘用系统默认图标**：首版不做专属美术资源。
- **不接管手工启动的核心**：壳发现核心锁被占就报错退出，不会「探测到就开窗」。
- **窗口位置不落盘**：本次运行内记住窗口状态，重开壳回到默认（最大化）。

## 回滚

不启动壳即回到现状；要彻底删掉这个 change 的痕迹：

1. 删除 `shell/` 目录与 `scripts/build_desktop_shell.ps1`；
2. 删除 `.gitignore` 里 `shell/dist/`、`shell/**/bin/`、`shell/**/obj/` 三行；
3. **必须同时删除 `test/unit/desktop_shell_docs_test.dart`**（或与壳一起保留）：这条守卫要读
   `shell/AliasAgent.Desktop/DesktopOptions.cs` 里的 `DefaultCorePort`，只删 `shell/` 会让它
   因为读不到 C# 常量而长期红——不许只删一边让它红着。
4. 配置里的 `core` 块可以留着（旧版本保存一次配置会丢掉它，与 `profile` 块同一类降级边界）。

核心侧不受影响：`core.shutdown` 是新增方法，不调用就无影响；`core.port` 是新增可缺省块。

```powershell
# 无窗口自检（起核心 → 就绪 → 静态页 → 停机 → 锁释放；不开窗、不建托盘）
shell\dist\AliasAgent.Desktop.exe --selftest

# 冒烟（单独跑；不进 run_all.sh 聚合链，因为那条链的 04/05 会起窗）

```
