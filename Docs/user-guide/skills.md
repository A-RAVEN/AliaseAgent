# 技能（skills）

**一句话**：把"你希望助手反复遵循的一套做法"写成一个文件夹放进固定位置，助手在对话里遇到匹配的活就会自己翻开它照着做 —— 不用每次复制粘贴提示词。

> 技能格式遵循开放规范 Agent Skills（本仓库事实源：`Docs/AgentSkillsDoc.md`），和 Claude Code 等工具用的是同一种 `SKILL.md` 格式：你已有的技能文件夹可以直接放进来。

---

## 装在哪、怎么算装上

技能目录固定是 `~/.aliasagent/skills/`（`~` 就是你的用户主目录，Windows 实写如 `C:\Users\你\.aliasagent\skills\`）：

```
~/.aliasagent/skills/
└── my-skill\               ← 一个技能一个文件夹
    ├── SKILL.md            ← 必需：技能本体
    ├── references\         ← 可选：助手按需读取的参考文档
    ├── scripts\            ← 可选：可执行的脚本（由助手用 run_command 跑）
    └── assets\             ← 可选：模板、数据文件
```

**把文件夹放进 `skills\` 目录，下一条消息就生效（无需重启）** —— 没有开关、不需要在任何模板里勾选，所有对话（包括子 Agent）都会看到它。卸载就是删文件夹，同样下一条消息就看不到它了。

## SKILL.md 怎么写

文件开头用两行 `---` 夹着一段 YAML 信息，之后是给助手看的正文（Markdown，没有格式限制）：

```markdown
---
name: my-skill
description: 一句话说明这个技能做什么、什么时候该用它。
---

## 步骤
1. ……
```

| 字段 | 必填 | 限制 |
| --- | --- | --- |
| `name` | 是 | 1–64 个字符；只能小写字母、数字、单个 `-` 分隔；不能以 `-` 开头或结尾、不能连写 `--`；**必须和文件夹名一模一样** |
| `description` | 是 | 1–1024 字符，非空；助手就靠这句话决定要不要翻开你的技能，把"什么时候用"写进去 |
| `license` / `metadata` / `allowed-tools` | 否 | 本应用不执行 `allowed-tools`（本产品全权限零审批，见 CLAUDE 立场）；其余原样接受 |
| `compatibility` | 否 | 若写则 1–500 字符，声明环境要求；本应用只记录不校验 |

写在这个集合之外的字段（例如 Claude Code 的 `context: fork`、`model`）**会被忽略、不报错** —— 带着它们技能照常可用。

> **注意**：Claude Code 的技能正文里可以用 `` !`命令` `` 预先注入运行结果 —— 那是 Claude Code 独有的功能，**本应用不会执行 `SKILL.md` 里的任何命令**，那一行会原样作为文字给助手看。

## 助手什么时候用它

每一轮请求里，助手看到的不是技能全文，而是一张目录（每个技能的 `name` + `description`）。它觉得某个技能跟当前的活相关，才会调用 `load_skill` 把正文读进来；正文太长时和命令输出一样只给头尾预览，中段可以用 `read_spill` 按引用取回（预览长度是配置项 `spill.preview_chars`，规则与 `run_command` / `web_fetch` 完全相同，含"内联预览会换行归一、非法 UTF-8 字节显示为 U+FFFD，落盘文件仍是原始字节"的同一口径）。你也可以在对话里直接点名"用 my-skill 那个技能"，助手会先加载再执行。

提示词里常年带一段创建简则，助手随时可以帮你写新技能 —— 你直接说"帮我做个某某技能"就行，它会按 `SKILL.md` 的格式建好文件夹和 frontmatter（本节上方有同一份字段说明；写得不对时界面会提示原因）。

## 出错时你会看到什么

| 场景 | 表现 |
| --- | --- |
| 某个技能校验失败（比如 `name` 超长、和文件夹名不一致、没写 frontmatter） | 该技能**不生效**，界面上方出现一行提示，写明技能名和失败原因；改好文件后，下一条消息即恢复（无需重启） |
| 技能目录整体读不了（例如那个位置被放了一个同名文件） | 出现一行"技能目录不可读"提示，其余功能不受影响 |
| 助手请求加载一个不存在或校验失败的技能 | 工具卡显示失败原因（含技能名），不会拿到内容 |
| `skills\` 目录压根不存在 | 什么提示都没有 —— 没装技能就是默认状态 |

## 已知限制

- **空闲时不秒级生效**：改了技能文件要等到**下一条消息**（应用在每轮请求装配前看一眼技能目录，没在跑对话时不会主动刷新；文件监听式的秒级生效是后置的另一期）。
- **同修改时间且同大小的覆盖写可能不被发现**：刷新只看文件的修改时间与大小两个数；一次覆盖写如果让这两个数都没变（例如同一秒内写成同样长度），这次改动要等文件下次真正变动才被看见 —— 和 `edit_file` 的版本检查是同一类限制。
- **只有全局目录**，没有"某个项目专用技能"这一层。
- **没有管理界面**：安装、卸载、查看都是文件操作。
- 附属文件的名字目前建议只用 ASCII（中文文件名可能因 C++ 窄字符路径读不到，已登记缺陷清单）。
- `/斜杠命令` 式的显式触发（输入 `/my-skill`）是后置的另一期，本期待助手自己按描述选用。
