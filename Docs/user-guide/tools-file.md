# 文件工具

## 这是什么

让模型自己读写你电脑上的文件。共六个工具：`read_file`、`write_file`、`edit_file`、`list_dir`、`glob_file`、`grep_file`。

**这六个都是模型自己调用的，你不需要（也无法）手动点它们。** 你在输入框里说要做什么（例如"把 README 里那句话改掉"），模型会自己决定调哪个工具；每次调用都会在对话里出现一张卡片，展开能看到它读了哪个文件、改了什么。

## 在哪用

你只需要知道两件事：**能碰哪些路径**，以及**卡片上的结果是什么意思**。

## 工作区边界（最重要的一条）

- 所有路径都**相对于工作区**解析，工作区就是**你的用户主目录**（`%USERPROFILE%`，例如 `C:\Users\你的名字`）。
- 写 `notes.txt` 就是操作 `C:\Users\你的名字\notes.txt`。
- **越界会被拒绝**，不会悄悄放行。几种拒绝的原文：

| 返回的错误 | 什么时候出现 |
|---|---|
| `Access denied: path outside workspace` | 路径指到工作区外面（例如 `..\..\Windows\System32\drivers\etc\hosts`） |
| `path traversal not allowed (..)` | 路径里带 `..` |
| `absolute path not allowed` | 直接给了绝对路径（例如 `C:\Windows\notepad.exe`） |
| `No workspace set` | 应用还没设置工作区（正常启动时一定会先设置好） |

> 也就是说：**模型只能在你主目录里动手**。它读不到 `C:\Windows`，也改不到 D 盘上的项目 —— 除非那个项目正好在你的用户主目录里。

## 六个工具分别干什么

### `read_file` —— 读文件

| 参数 | 含义 |
|---|---|
| `path` | 文件路径（相对工作区） |
| `offset` | 从第几行开始读（从 1 数起），默认第 1 行 |
| `limit` | 读多少行，默认 2000，最大 2000 |

返回带行号的内容（`1`、`2`、`3`…）。**超过 2000 行会被截断**，要读后面得再调一次，把 `offset` 往后挪。

**怎么往后读：不用自己算行号。** 被截断时返回里会多一句能照抄的提示，例如：

```
File has 2050 lines, showing 1-2000. To continue reading, call read_file with {"path": "<same path>", "offset": 2001, "limit": 2000}.
```

照着那句里的 `offset` 再读一次即可（`2050` 是文件总行数，`1-2000` 是这次给了哪一段）。模型自己会照做；你也可以在对话里直接说"继续读这个文件剩下的部分"。

### `write_file` —— 新建或整份覆盖

| 参数 | 含义 |
|---|---|
| `path` | 文件路径 |
| `content` | 完整的新内容 |

它会**覆盖**原文件（不是追加）。卡片上的结果是 `Created <路径> (N bytes)`（新建）或 `Wrote <路径> (N bytes)`（覆盖），括号里是写入了多少字节。目录不存在会自动创建。

### `edit_file` —— 改文件里的几处文字

| 参数 | 含义 |
|---|---|
| `path` | 文件路径 |
| `edits` | 一批替换，每项是 `old_text`（要找到的原文）、`new_text`（换成什么）、`replace_all`（要不要替换所有出现处，默认否） |

一次调用可以带**多处**替换（最多 100 处）。规则：

- **必须先读过这个文件**：同一轮对话里没有先 `read_file` 过它，`edit_file` 会直接拒绝，错误里带 `read the file first`。先让它读一遍再改即可（刚用 `write_file` 建出来的文件算已读过）。
- **文件在你读过之后被改过，会被拒绝**：错误里带 `file changed since it was read; read it again before editing`。这时重新读一遍再改就行——这是为了防止它按旧内容改，把你或别的程序刚写进去的东西覆盖掉。
- **先整批检查，再动手**：只要有一处找不到原文，**整个文件一个字都不改**，返回错误。
- 找到**多处**而你没让它全替换 → 拒绝，并告诉你出现在哪几行。
- 两处替换的范围**重叠** → 拒绝。
- 空白差别会被自动容忍（例如原文用的是空格、文件里是 Tab，或者换行符是 Windows 的 CRLF）：这时结果里会多一句 `— matched with ...`，说明是靠"忽略空白差别"匹配上的。
- 拒绝的情况还有：文件里有 NUL 字节（当二进制看）、文件大于 1MB、目标是目录、`old_text` 是空字符串。

改成功之后，卡片标题会显示 `edit_file(<路径>) +N/−M`（N 是新增行数、M 是删除行数，折叠着也能看到）。点开 `Expand result` 会显示这次的差异：红色 `-` 开头是原来的行，绿色 `+` 开头是新的行，每段前面标着它在文件里的起始行号（`第 12 行`）。一次改得太多时，默认只显示前 12 行，剩下折成一句 `还有 N 行未显示，点击展开`，点一下就看全。

### `list_dir` —— 列一层目录

| 参数 | 含义 |
|---|---|
| `path` | 目录路径 |

只列这一层，不递归。

### `glob_file` —— 按文件名样式找文件

| 参数 | 含义 |
|---|---|
| `pattern` | 文件名样式，例如 `lib/**/*.dart`；支持 `*`、`**`、`?` 和 `!` 取反 |
| `max_results` | 最多返回多少条，默认 200 |

返回的是相对路径，一行一个。结果被截断时会多一行 `... (truncated, showing X of Y)`。默认会跳过被 git 忽略的文件。

### `grep_file` —— 按内容找

| 参数 | 含义 |
|---|---|
| `pattern` | 正则表达式 |
| `glob` | 只看哪些文件（可选），例如 `lib/**/*.dart` |
| `ignore_case` | 忽略大小写，默认否 |
| `max_results` | 最多返回多少条，默认 100 |

返回格式是 `路径:行号: 那一行的内容`。**注意：一旦你填了 `glob`，被 git 忽略的文件也会被搜**（这是它与默认行为的区别）。一条都没搜到时返回 `(no matches)`。

## 出错时会看到什么

| 卡片上的现象 | 含义 | 下一步 |
|---|---|---|
| 卡片状态是 `Error`，结果里是上面的越界文案 | 模型想访问工作区外面的路径 | 把你的要求改写成主目录里的路径，或者把文件先复制进主目录 |
| `File too large for edit_file (>1MB)` | 文件超过 1MB，这个工具改不了 | 让模型用 `write_file` 整份重写，或者你自己改 |
| `Cannot edit binary or non-text file` | 文件是二进制（或 UTF-16 之类） | 这类文件别交给模型改 |
| 多处匹配被拒，错误里带行号 | 要替换的原文在文件里出现了不止一次 | 让它把上下文写长一点再试 |
| `cannot edit "…": read the file first` | 这个文件在本次运行里还没被读过 | 让它先读一遍再改 |
| `cannot edit "…": file changed since it was read` | 你（或别的程序）在它读过之后改了同一个文件 | 让它重新读一遍再改 |
| 卡片上是 `diff 未显示：改动过大（N 处改动）` | 这次改动太多，完整差异没有带回来 | 改动本身已经生效；要核对就自己打开文件看 |

## 限制

- **只能在你主目录里动手**，且不能写绝对路径、不能带 `..`。
- **`read_file` 一次最多 2000 行**：大文件要分段读。注意"读过一次"按整个文件算，所以被 2000 行截断时，没读到的那部分也会被允许改。
- **`edit_file` 有 1MB 上限**，且改的是文字文件；它对**新建文件**无能为力（用 `write_file`）。
- **只有 `edit_file` 有"先读再改"和"改过就拒"这两层保护**；`write_file` 覆盖文件不受它们保护，模型可以直接整份重写。
- **版本检查看的是修改时间与文件大小**：外部程序若只改内容、既不改修改时间也不改大小，这层检查发现不了。
- **这些工具不弹确认框**：模型一旦调用就直接执行。要限制它能碰什么，办法是别把重要文件放在主目录里被它看到，或者干脆从配置的 `tools` 里去掉这些工具（见 [配置](configuration.md)）。
