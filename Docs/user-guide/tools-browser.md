# 浏览器工具

## 这是什么

让模型开一个**真实的浏览器窗口**（你机器上的 Edge 或 Chromium），自己打开网页、点按钮、填输入框、读页面文字。共四个工具：`browser_navigate`、`browser_click`、`browser_type`、`browser_snapshot`。

**这四个都是模型自己调用的，你不需要（也无法）手动点它们。** 但因为用的是真实窗口，**你会亲眼看到它自己动** —— 这是设计如此，不是出 bug。

## 在哪用 / 前提

- **需要本机装好 Playwright 和可用的 Edge 或 Chromium**。应用启动时会先探一次；**探测不通过时，这四个工具根本不会出现**（模型看不到它们，也不会说自己在用浏览器）。
- 那个探测**不是工具**：它只是启动时问一句"浏览器能不能用"，模型不能调用它。

## 怎么操作

正常提问就行。典型过程：`browser_navigate` 打开一个网址 → `browser_snapshot` 读页面文字 → `browser_click` 点某个元素 → 再读一次。**这几步共用同一个浏览器会话**（同一个窗口、同一批标签页），所以上一步打开、下一步还在。

| 工具 | 参数 | 干什么 |
|---|---|---|
| `browser_navigate` | `url` | 打开网址，返回页面文字 |
| `browser_click` | `selector` | 按 CSS 选择器点一个元素，返回点击后的页面文字 |
| `browser_type` | `selector`、`text` | 往输入框里填字，返回填完后的页面文字 |
| `browser_snapshot` | 无 | 重新读一次当前页面（实时读取，不是缓存），返回页面文字 |

返回给模型的是**页面文字**（标题、网址，然后是正文）；页面读不出文字时是 `(no page text captured)`。

## 点开会新标签页的链接会怎样

**会跟过去**：点到 `target=_blank` 的链接（或 target 写成具名窗口的链接）、或者页面自己用脚本弹出来的新窗口时，应用会切到那个新标签页，后续操作都在新页面上做（写进日志里的说法是 adopted tabs）。

**但等待是有上限的**：点击之前会先看一眼这个链接是不是要开新页 —— 是要开新页的，点击之后最多等 **5 秒**；普通点击（原地跳转）仍然是 **1 秒**。新页面只要出现就立刻跟过去，不会白等到上限。超过该上限才停在原页面，返回的还是旧页面的文字 —— 遇到"点了没反应"的情况，可以让模型再点一次或直接让它打开目标网址。

## 出错时会看到什么

| 现象 | 含义 | 怎么办 |
|---|---|---|
| 模型说自己没法用浏览器，工具清单里也没有那四个工具 | 启动时探测没通过（缺 Playwright、或找不到可用的 Edge/Chromium） | 装好 Playwright 与 Edge/Chromium 后重启应用 |
| 卡片状态 `Error`，结果是 `browser unavailable (python/playwright/script path)` | 运行中要开浏览器时发现环境不全 | 同上；也可以看日志里更早的那几行 |
| 点了元素但页面没变化 | 选择器没匹配到、或者元素被遮挡 | 让模型先 `browser_snapshot` 看页面结构，换一个选择器 |
| 页面文字是空的或只有很少几行 | 页面正文靠脚本后加载，读得太早 | 让模型再读一次 |

## 限制

- **不下载文件**：页面上任何下载都会被取消，**不会在你磁盘上留下文件**。
- **不弹权限请求给你**：摄像头、定位、通知这类权限一律**直接拒绝**，不会问你。
- **只看文字**：它是把页面文字读给模型，**不截图、不看图**。纯图片内容、验证码、图形验证它做不了。
- **要登录的站点**：它不会拿你的账号去登录（没有你的密码，也不会自动填）。
- **选择器要写对**：点击和填字都按 CSS 选择器定位，页面结构一变就可能失败。
- **窗口是真的**：它开着窗口占用你的桌面；关掉那个浏览器窗口后，下一次调用会重新开一个。
- **新标签页最多等 5 秒、普通点击最多等 1 秒**（见上；要开新页的链接先被认出来，才用较长的那个上限）。
