# 上下文压缩

## 这是什么

对话变长以后，模型装不下全部内容。应用会把**较早的那部分对话**交给模型压成一条摘要，之后的每轮请求里就用这条摘要代替原文，这样对话可以一直继续下去。

摘要是**自动**发生的，界面上没有开关按钮；要调就改配置。

## 什么时候会压缩

阈值这样算：

```
阈值 = 模型能装下的总 token 数 × compaction_threshold_percent ÷ 100
```

举个例子：模型能装 100 万 token，百分比是 25，阈值就是 25 万 token。

**攒够阈值就压，不等把窗口装满**：从最早的内容开始往后累加，累加超过阈值，就把这一批压成一条摘要。

两个数这样来：

| 数 | 从哪来 |
|---|---|
| 模型能装下的总 token 数 | 配置里 `agent_types` → `general` → `max_context_tokens`；不写就再弹一次欢迎对话框问你要 |
| 百分比 | 配置里 `compaction_threshold_percent`，缺省 25（也就是 25%）；写了 `0`、负数、大于 `100`、小数、字符串都会被当成没写，按 25 走，并在日志里打印一行提示 |

## 有两级

| 级别 | 做什么 | 什么条件下发生 |
|---|---|---|
| 第一级 | 把**一段对话**（若干条消息）压成**一条摘要** | 这一段累积超过阈值 |
| 第二级 | 把**已经生成的若干条第一级摘要**再合成**一条更粗的摘要** | 这些摘要合起来又超过同一个阈值 |

两级用的是**同一个阈值算法**，没有别的门槛。

## 界面上怎么认出来

压缩后，摘要会当成**一条消息**发给模型，开头带一个标记：

- 第一级：`## 更早上下文(压缩xN,非用户发言)`
- 第二级：`## 更早上下文(压缩xN,层级2,非用户发言)`

想看到它：发几轮消息让对话变长，切到「真实上下文」那一屏（见 [真实上下文视图](real-context-view.md)），排在最前面的那条就是摘要。

## 原文去哪了

**还在本地数据库里**，没有删。只是这一轮的请求里不再发送原文，改用摘要。

## 会花钱

生成摘要要走一次模型调用 —— **这一步是要计费的**。阈值调得越低，压得越勤，调用越多。

## 怎么调

改配置里的 `compaction_threshold_percent`（1 到 100 的整数），重启应用：

```json
{
  "agent_types": {
    "general": {
      "max_context_tokens": 200000,
      "compaction_threshold_percent": 25
    }
  }
}
```

- **调小**（例如 10）：更早开始压缩，单次请求更省 token，但更早丢掉细节。
- **调大**（例如 80）：保留更多原文，但单次请求更贵，也可能更快撞到模型上限。

## 限制

- **压缩是有损的**：原文不再发给模型，摘要里没写到的细节，模型就看不到了。
- **摘要是模型写的**：它可能漏掉或写错内容。想让某些内容永远不丢，把它们写进 `standing_requirements`（见 [配置](configuration.md)）。
- **没有手动触发按钮**：只能靠改阈值和对话长度来让它发生。
- **`max_context_tokens` 必须填对**：填得比模型实际能吃下的大，阈值也会跟着变大，压缩就会来得太晚。
