# 命令行工具（run_command）

**一句话**：让助手在你自己的电脑上真的执行一条命令，并把结果读回来 —— 这样它改完代码可以自己跑测试、跑构建、跑 git，不用每一步都回来找你。

> **这是模型调用的工具，不是界面上的按钮。** 你在对话里提出要求（例如"跑一下单元测试"），助手决定调 `run_command`，你在对话里看到的是一张工具卡：上面是它要执行的命令，下面是执行结果。

---

## 它在本机的什么位置执行

- 用**你自己的 Windows 账户与权限**执行，不是沙箱、不是虚拟机，也没有"先问你一下再执行"这一步。
- 命令**真的会改动磁盘**：它会写文件、会装东西、会删东西，和你在终端里自己敲是同一种效果。
- 跑起来之后**不能事后批准或撤销**。要停只能等它自己结束、到超时被终止，或者你直接关掉应用。
- **解释器固定是 PowerShell**（先找 PowerShell 7，找不到就用系统自带的 Windows PowerShell 5.1）。所以命令要按 PowerShell 的写法写：路径用 `C:\...` 这种原生形式，读环境变量用 `$env:NAME`。写 `dir /b` 这类 cmd 写法或 `ls -la` 这类 bash 写法会报语法错。

## 参数怎么填

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `command` | 是 | 要执行的 PowerShell 命令。可以多行。 |
| `workdir` | 否 | 这条命令在哪个目录里跑。缺省是你的工作区根目录；相对路径按工作区解析。**指向工作区之外的路径会被拒绝，命令不会执行**（这是"参数填写规范"，不是安全边界 —— 命令本身仍然可以访问别处）。 |
| `timeout_ms` | 否 | 这条命令最多跑多少毫秒。不填按配置里的缺省值，填得比上限大就按上限跑。 |

**每次调用都是一个新进程**：上一条命令里的 `cd`、设置的变量都不会留到下一条。要换目录就填 `workdir`，不要在命令里 `cd`。

### 可以直接抄的几条

在对话框里这样说，助手就会去执行（下面这些都在本仓库实测跑通过）：

| 你想做的事 | 可以对助手说 | 它实际会执行的命令 |
| --- | --- | --- |
| 跑一个测试文件 | "跑一下 summary_reference 那个测试" | `flutter test test/unit/summary_reference_test.dart`（实测输出末行 `All tests passed!`） |
| 跑整套单元测试 | "跑全套单元测试" | `flutter test` |
| 看仓库当前状态 | "看看 git 状态" | `git status --short` |
| 编译 C++ 边车 | "重新编译 sidecar" | `cmake --build sidecar/build/windows --config Debug` |
| 跑 C++ 测试 | "跑 C++ 测试" | `ctest --test-dir sidecar/build/windows -C Debug` |

一条跑几分钟的命令（例如整套测试），期间对话框不会有进度，跑完才有结果；如果超过了 `command_timeout_ms`，会被终止并在结果里标 `[timed out after ...ms]`。

## 两个可调的配置项（外加一项预览长度）

超时那两项写在 `~/.aliasagent/config.json` 的 `agent_types` → 你的 Agent 类型（缺省是 `general`）段里；预览长度写在顶层的 `spill` 块里：

```json
{
  "agent_types": {
    "general": {
      "command_timeout_ms": 120000,
      "command_max_timeout_ms": 600000
    }
  },
  "spill": {
    "preview_chars": 1000
  }
}
```

| 配置键 | 缺省值 | 含义 |
| --- | --- | --- |
| `command_timeout_ms` | 120000 | 一条命令缺省最多跑多少毫秒（2 分钟） |
| `command_max_timeout_ms` | 600000 | 上限（10 分钟）。填得比它大也按它跑 |
| `spill.preview_chars` | 1000 | 结果里**头尾各保留多少字符**；判"要不要省略"的阈值是它的 2 倍（2000 字符）。填非正值按 1000 算 |

键缺失、写成零 / 负数 / 文字时，各自回落到自己的缺省值，工具照常能用。这几个键会在你第一次保存配置时自动写回文件里，方便你找到它们。

**两个旧键已废弃**：`command_max_output_chars` 与 `command_output_full_chars` 不再有任何作用（它们描述的是旧行为"只留尾部 + 写系统临时文件"）。配置里还留着它们时，应用会打一行"已废弃，改用 `spill.preview_chars`"的告警并忽略。旧配置长这样，**可以直接删掉这两行**：

```json
{
  "agent_types": {
    "general": {
      "command_max_output_chars": 8000,
      "command_output_full_chars": 2000000
    }
  }
}
```

## 你会看到什么

结果按这个顺序拼出来：

1. 命令的**标准输出**——输出太长时，这里是**头尾预览**："头部前 `preview_chars` 个字符 + 一行省略说明 + 尾部后 `preview_chars` 个字符"；
2. 如果有标准错误，加一段 `[stderr]` 再跟标准错误的内容；
3. 一行 `[spill refs: stdout=<文件路径> (<总字节数> bytes, <省略字节数> omitted) — read any byte range back with read_spill(...)]`，说明完整输出在哪、被省略了多少、怎么读回；
4. 超时时跟一行 `[timed out after <毫秒数>ms]`；
5. **退出码不是 0 时**才跟一行 `[exit code: N]`。

**退出码不是 0 不算工具失败**：命令跑了、跑完了、退出码是几，都会被如实报出来 —— 助手据此判断"测试挂了"还是"命令本身没写对"。什么都没输出时显示 `(no output)`。

常见错误原文：

- `工作目录不允许在工作区之外：<路径>` —— `workdir` 填到了工作区外面，命令没有执行。
- `工作目录不存在或不是目录：<路径>` —— 那个目录不在。
- `command 不能为空` —— 没给命令。
- `找不到 PowerShell：已依次查找 …` —— 四个位置都没找到 PowerShell；本工具不会改用别的解释器。
- `命令没能启动：解释器或工作目录无法使用（…）` —— 起进程失败。

## 长输出怎么读回（`read_spill`）

命令输出超过 2000 字符（`spill.preview_chars` 的 2 倍）时，助手拿到的是头尾预览，中间那段在磁盘上。它（或者你让它）用 `read_spill` 按字节读回来：

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| `ref` | 是 | 结果里那个 spill 文件路径（`spill refs: ...` 那一行给的就是它）。**只认 spill 目录里的文件**：给别的路径会被拒绝，理由是"引用不在 spill 根目录内" |
| `offset` | 否 | 从第几个**字节**开始读，缺省 0。注意是字节不是字符 —— 中文一个字 3 个字节 |
| `limit` | 否 | 读多少**字节**，缺省是 `spill.preview_chars` 的 2 倍（缺省配置下 2000） |

读回来的就是文件里那一段原文，逐字节一致。四种看不明白时该看到的提示：

- `引用不在 spill 根目录内：<路径>` —— `ref` 指到 spill 目录外面了（这是故意的限制，`read_spill` 不是通用文件读取器；读工作区里的文件请用 `read_file`）。
- `引用不存在：<路径>` —— 文件没了（会话被删、或目录被手动清过）。
- `读取区间越界：offset=… limit=… total_bytes=…` —— 要的区间超出文件长度，不会"能读多少给多少"。
- `切点落在多字节字符中间：offset=…` 或 `区间末尾落在多字节字符中间：offset+limit=…` —— 切点正好劈开一个中文字，改成整字符边界再读。

**写盘失败会看到什么**：输出不超过预览阈值时，结果里直接是全文（写盘失败不影响你看结果）；**超过阈值又写不进去**时，整条结果会是失败，错误文本里写明是哪条流（标准输出 / 标准错误）、写到哪个目录、以及系统给的原因 —— 不会只给你一段内容冒充完整结果。

## 结果里的换行与坏字节被改过（预览是这样，文件不是）

结果正文（给模型看的头尾预览）会做两件事，而 **spill 文件里存的是原始字节**：

- **换行归一**：Windows 程序输出的 `CRLF` 会变成 `LF`（少一个字节，省 token，也免得同一段内容两种换行）；
- **坏字节替换**：输出里不是合法 UTF-8 的字节会被换成替换字符 `U+FFFD`（`�`）。

所以"预览里看到的字节数"可能比文件小。要拿原始字节，一律用 `read_spill` 读文件——它返回的区间与文件逐字节相同，不做上面这两件事。

## spill 目录什么时候被删

- **删会话时**：该会话的目录 `~/.aliasagent/spill/<会话 id>/` 整个删掉；
- **每次启动时**：`~/.aliasagent/spill/no-session/`（没有会话 id 时落进去的、以及测试留下的 `_it_*`）会被清掉 —— 这类目录对应不到任何会话，只增不减，所以启动时收拾一次；
- **不设保留天数**：没有"三天后自动清"这种策略，也不占用工作区、不会被 git 追踪。


## 已知限制

- **没有常驻会话**：每次调用都是新进程，`cd` 与变量不跨调用保留。
- **没有后台执行**：命令跑完（或被超时终止）才返回；一条跑十分钟的构建，这十分钟里对话框不会有这条命令的进度，只有结束后的结果。
- **不做方言翻译**：只认 PowerShell。cmd 与 bash 的写法会报错，需要你自己换成 PowerShell 写法。
- **中文参数的支持程度以实测为准**：命令与工作目录里的中文已经能正确传进去（这一条有测试守着）；但**被执行的程序自己怎么读命令行**不由本工具决定，个别老程序可能仍读不到非 ASCII 参数。
- **工作区之外的 `workdir` 会被拒绝**，但命令本身仍可访问工作区之外的路径（这里没有权限模型）。
- **完整输出存在 spill 文件里，随会话删除**：每个会话的输出都在 `~/.aliasagent/spill/<会话>/` 下；删掉那个会话时整个目录一起删掉。**不设保留天数**（不会"三天后自动清"），也不占用工作区、不会被 git 追踪。
- **超时只能整条命令为单位**：到点杀的是这条命令以及它拉起的全部子进程，不能只停其中某一个。
