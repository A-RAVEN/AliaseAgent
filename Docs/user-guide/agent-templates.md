# Agent 模板

## 这是什么

Agent 模板是一份"用哪个模型、带哪些工具、上下文多大"的可复用配置。每个会话在创建或恢复时按自己保存的模板名选一份模板，生成一个运行中的 Agent 实例。

应用自带 `general` 模板；你可以再添加自己的模板（例如一个只读代码评审模板、一个能用命令行的高权限模板）。

## 在哪用

在**会话侧栏**，`New Chat` 按钮下面有两个入口：`Agents`（模板）与 `Providers`（供应商与模型目录，见 [Provider 与模型目录](provider-models.md)）。

界面文案：`Agents`

点开后会列出所有模板，每一行显示：模板名、模型、推理强度。列表底部有一句生效时机说明：

界面文案：`保存只影响之后创建或恢复的实例；已经运行的实例继续使用创建时的配置。`

## 怎么操作

### 添加模板

1. 点侧栏 `Agents`。
2. 点 `添加模板`（界面文案：`添加模板`）。
3. 填写模板名、选 provider、填模型（可以从右侧目录下拉选，也可以直接手输）、选推理强度、填系统提示词、勾工具与输入模态、填上下文窗口。
4. 点 `保存`。

模板名只在**添加时**填写；创建之后不能改名。修改模式下模板名输入框是只读的，界面上有这句提示：

界面文案：`模板名创建后不可修改（只读）`

### 修改模板

1. 点侧栏 `Agents`。
2. 点某个模板右侧的铅笔按钮（提示文字：`修改模板`）。
3. 改完点 `保存`。

修改会写回 `~/.aliasagent/config.json` 的 `agent_types` 段，并立刻更新模板列表。**已经运行的会话不会热更新**：它继续用创建时那一份配置。要让某个已打开的会话马上用上新配置，用下面「给当前会话换模板」的切换控件；只在会话列表里重新选中它不会重建实例。

### 给当前会话换模板

不用新建会话，也不用重启，就能让**当前这个会话**换一个模板 —— 聊天记录和工具输出都不会丢。

1. 在聊天区顶部的**当前会话工具栏**（`对话视图` / `真实上下文` 两个按钮同一行）右侧，找到模板下拉框；它显示当前会话正在用的模板名。
2. 选另一个模板。
3. 切换完成后，这个会话的**下一次请求**就使用新模板的模型、推理配置、系统提示词与工具。

切换时发生的事：

- 旧的 Agent 对象**退役**：它不再接受新的发送，但正在跑的那一轮（模型、工具、写库与后台压缩写库）会自然跑完，不会被中断。
- 新实例沿用同一个会话句柄与工作区：聊天记录、工具记录、摘要，以及工具输出**溢出**文件都保留。切换前模型拿到的 `read_spill` 引用切换后仍然可读；新产生的溢出文件用新的文件名，不会覆盖旧引用。
- 数据库里 `sessions.agent_type` 更新成新模板名，重启应用后仍按它重建实例。
- 只影响这一个会话；其它会话的实例与消息不变。

选择控件**不可用**（点不动）的三种情况：

- 工具清单还没准备好；
- 没有当前会话 —— 这时**直接输入并发送仍然可以**，应用会自动创建一个 `general` 会话；
- 这个会话正在切换，或正在删除。

切换期间不能发送：发送按钮禁用，按回车也不会发出去（输入内容保留）。

界面文案：`正在切换 Agent 模板…`

界面文案：`正在切换 Agent 模板：完成后才能发送`

切换失败时，界面顶部红条写出**失败阶段**与**候选模板名**：

| 红条里的阶段 | 意思 |
|---|---|
| `候选预检` | 模板不存在、provider 未定义、窗口非法或工具名未知；旧实例、数据库与选择框都没有变化 |
| `退役旧实例` | 旧实例没能安全退役；它仍在运行，数据库没有变化 |
| `持久化 agent_type` | 数据库没有更新到这一行（例如会话已被删除）；不会创建新实例 |
| `创建新实例` | 数据库已经是新模板名，但新实例没建起来；红条继续显示，选择框显示数据库里的实际值，下一次发送会按它重新创建实例 |

失败后选择框显示的是数据库里**实际保存**的模板名，不会静默退回 `general`。

### 换模型时确认窗口

模型换了，上下文窗口通常也要跟着换。所以在修改模板时，如果改了模型，保存前会弹出一个确认框：

界面文案：`确认上下文窗口`

确认框里让你当场核对新模型适用的窗口值；点 `取消` 就不保存。

## 字段含义

| 字段 | 填什么 |
|---|---|
| 模板名 | 唯一名字；创建后不可改。会话按这个名字引用模板 |
| provider | 从 `config.json` 的 `providers` 里选一个（也就是 `Providers` 页里列出的那些名字）。**模板编辑器不显示密钥**；增删改 Provider 与密钥到 `Providers` 页做 |
| 模型 | 模型名，例如 `claude-sonnet-4-6`、`deepseek-v4`；不能为空。右侧目录下拉来自该 Provider 的模型目录（显示网关给的 `display_name`，值是模型 id），也可以直接手输目录外的名字 |
| 推理强度 | 有目录时，选项 = 目录档位与执行层合法集合的交集；目录里的 none 映射为"关闭"。没有目录时就是 `关闭` 或 low / medium / high / xhigh / max 之一 |
| 系统提示词 | 这个 Agent 的角色说明；可以多行 |
| 工具集合 | 勾选允许模型调用的工具；选项来自当前真实可用的工具目录。勾上 `spawn_subagent` 后这个模板创建的 Agent 才能让子 Agent 干活（见 [子 Agent](agent-subagents.md)） |
| 输入模态 | text / image 两项：模型能不能收文字与图片。网关目录里的 video 等取值只会记录，不会出现在这两个勾选项里 |
| 上下文窗口 | 正整数（token 数）；它决定占用环的整圈与压缩阈值（窗口 × 百分比） |

选中目录里的模型后，编辑器会用目录值预填窗口、输入模态与推理强度（详见 [Provider 与模型目录](provider-models.md) 的"在模板里选模型"）：窗口未知时留空并提示"目录未提供窗口，请手填（压缩阈值依赖它）"；目录档位不被执行层支持时会显示一行"目录档位 X 暂不被执行层支持，未列入"，不静默消失。预填只是默认值，改完保存以你填的为准；目录后续刷新**不会**回改已保存的模板。

目录外手输模型时，界面显示中性提示"不在最近一次目录中"，**不会**阻断保存；没有 Provider 时编辑器显示"请先在 Providers 页添加供应商"并禁用保存。

这些字段最终都写进 `config.json`，对应的配置键是 `provider`、`model`、`thinking_effort`、`system_prompt`、`tools`、`max_context_tokens`。模板表本身的键是 `agent_types`。

```json
{
  "agent_types": {
    "general": {
      "provider": "magpie",
      "model": "claude-sonnet-4-6",
      "system_prompt": "You are a helpful assistant.",
      "tools": ["read_file", "write_file"],
      "thinking_effort": "high",
      "max_context_tokens": 200000
    }
  }
}
```

模板里没有出现在编辑界面的字段（例如 `input_modalities`、`compaction_threshold_percent`、`command_timeout_ms`、`standing_requirements`）在保存时会**原样保留**，不会被重置成默认值。

## 出错时会看到什么

保存失败时，错误显示在编辑器标题下面的红条里，**你填的内容都还在**，改对再点保存即可。

| 红条里写的 | 原因 | 怎么办 |
|---|---|---|
| `模板名不能为空` | 添加时模板名是空的 | 填一个名字 |
| `模型不能为空` | 模型输入框是空的 | 填模型名 |
| `模板名 "<名字>" 已存在：添加被拒绝，既有同名模板保持不变` | 添加了一个和现有模板同名的模板 | 换一个名字；要改原模板请点它的铅笔按钮 |
| `模板名创建后不可修改：只允许在添加时确定` | 试图改模板名 | 模板名只读；本版没有改名功能 |
| `provider "<名字>" 未定义：请从已配置的 provider 中选择` | 模板引用的 provider 在配置里不存在 | 换一个已配置的 provider，或先改 `config.json` 增加 provider |
| `上下文窗口必须是正整数（当前输入不合法）` | 窗口填了 0、负数或非数字 | 填正整数，例如 `200000` |
| `未知工具：<名字>（不在工具目录中，不会被静默删除）` | 工具清单里有当前不存在的工具名 | 取消勾选它；不会静默删掉后继续保存 |

界面文案：`上下文窗口必须是正整数（当前输入不合法）`

还有两类错误发生在**创建或恢复会话**时，显示在界面顶部红条（不是编辑器里）：

| 红条里写的 | 原因 |
|---|---|
| `Agent 模板 "<名字>" 的 max_context_tokens 无效（...）：必须是正整数。拒绝创建实例...` | 模板窗口缺失、为零或负数；这个模板不能创建实例，也不会按 0 继续发送全文 |
| `Agent 模板 "<名字>" 不存在：拒绝创建实例，也不会退回 general` | 会话保存的模板名找不到；不会偷偷改用 `general` |
| `未知工具：...：不在 ToolCatalog 中。不会静默丢弃；请修正模板的工具清单。` | 模板里的工具名在当前工具目录里不存在 |

## 生效时机

保存模板与"某个会话什么时候用上新配置"是两件事。分清三种情况：

1. **只是在会话列表里重新选中这个会话**：应用复用它在本进程里已经建好的 Agent 实例，配置**不变**（仍是创建时那份）。
2. **重启应用**：进程里的实例都没了，应用按数据库 `sessions.agent_type` 里保存的模板名重建实例 —— 这时才会读到保存后的模板新值。
3. **用工具栏的模板下拉显式切换**：立即退役旧 Agent 对象并创建新实例；切换之后的下一次请求就使用新模板（同一个会话，聊天记录与溢出文件都保留）。

另外：

- 保存模板 = 只影响**之后创建或恢复**的实例。
- 正在跑的实例持有创建时冻结的配置：模型、推理强度、系统提示词、工具、窗口、图片输入模态、命令超时、不可压缩要求都不变。
- 占用环的整圈也来自实例创建时窗口；模板窗口后来改小，旧实例的环不会跟着换分母。

## 限制

- 第一版**不支持删除模板**，也**不支持修改模板名**（避免既有会话的引用悬空或撞名覆盖）。
- Provider（供应商）在 `Providers` 页管理：模板编辑器只选名字、不显示密钥；改 Provider 与探测模型目录见 [Provider 与模型目录](provider-models.md)。
- 第一版没有"给单个实例覆盖字段"的入口；只能选模板。
- 没有删除入口意味着模板列表只会变长；如果确实需要清理，本版只能手改 `config.json` 的 `agent_types`。
- 旧版首启生成的 `["read_file", "list_dir"]` 两项默认清单会在启动时**可见地**升级成当前十一项基础工具；你自己改过的清单不会被迁移。
- 上一版的十项完整默认清单**不会**自动加上 `spawn_subagent`：它和"你主动删掉了它"在配置文件里完全相同，应用无法区分。要让某个模板用上子 Agent，请在编辑器的工具勾选区显式勾上并保存（见 [子 Agent](agent-subagents.md)）；显式删掉之后也不会被自动加回。
- 工具的可用性取决于当前环境：例如没有配置搜索服务时，`web_search` 不在目录里，保存含它的模板会被拒绝并报 `未知工具`。
