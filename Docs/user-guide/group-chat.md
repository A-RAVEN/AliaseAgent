# 群聊（组会话与成员）

> 适用版本：`agent-group-chat` + `group-reactive-mode`（自发反应）。群聊的界面**只在 web 端**
> （`dart run bin/alias_agent_core.dart` 之后用浏览器打开回环地址）；Flutter 桌面端只显示占位。

## 组是什么

一个**组**就是一条会话（`kind = group`），里面可以有多个**成员**。成员共享**同一份原文**：
用户消息、每个成员的公开回复、以及每个成员自己的思考与工具过程，全部存在这条会话下。

但每个成员看到的上下文并不是原文，而是原文的**一次投影**：

| 原文里的东西 | 成员 X 看到的 |
| --- | --- |
| 用户消息 | user 轮，原样 |
| X 自己的公开回复 | assistant 轮，第一人称（不带「X 说：」） |
| X 自己的思考 / 工具调用 / 工具结果 | 按历史重放（assistant 的思考与工具调用 + 工具结果） |
| 其他成员 Y 的公开回复 | user 轮，正文以「Y 说：」开头 |
| 其他成员的思考 / 工具调用 / 工具结果 | **整体不出现** |

所以：**别人只读得到你的公开回复，读不到你的过程**。每个成员都有自己的模型、窗口、
思考强度与压缩摘要（摘要也是各自私有的，不共享）。

## 在 web 哪里

1. 启动无头核心：`dart run bin/alias_agent_core.dart`（默认 serve `web/dist`）。
2. 浏览器打开核心回显的地址（`http://127.0.0.1:<port>`）。
3. **左侧会话列表常驻**：单聊与群聊同列混排（群聊行有「群」小标记），打开群聊、切回单聊、
   打开管理页都不会让列表消失。没有选中会话时主区是**空聊天屏**（标题「（未选择会话）」、
   输入禁用、不残留上一条会话的消息 / 快照）。
4. 左侧「＋ 组」新建一个组；点一个组会话 ⇒ **只切换右侧主区**进入群聊，列表仍在。
   群聊头部是两行：第一行是标题、取消反应链与（窄屏的）「成员」按钮；第二行是
   `[群聊 | 成员视图]` 双标签与组设置。

群聊主区是 `[群聊 | 成员视图]` **双标签**：

- **群聊（默认标签）**：公开时间线（中）+ 发送区（下）+ **成员名单（右侧）**。
  - 公开时间线：用户消息与所有成员的公开回复，按顺序排列，每条带作者。消息多时点
    右上角的「加载更早的消息」补更早一页（按作者与可见性各自归位，已移除成员的历史行
    也会出现）。
  - 成员名单在**右侧**：每个成员一张**成员卡片**（头像、名字、状态点、紧凑环、齿轮按钮），
    下方是「加入成员」。已移除成员仍显示（标「（已移除）」），卡片照常有头像与名字。
  - **公开时间线是聊天式左右气泡**：用户消息靠右（绿气泡，**用户头像**在这一行最右端）；
    成员消息靠左（**成员头像**在左、名字在气泡上方、气泡在右）。气泡宽度有上限，长文本
    在气泡内换行；气泡里的内容与旧版一致（附件缩略图与「图片未发送 / 图片已丢失」提示行都还在）。
  - **窄屏（窗口宽度小于 1280px）**：成员名单收进右侧**抽屉**，头部出现「成员」按钮
    （`aria-expanded` / `aria-controls`）；点开抽屉后成员卡片与「加入成员」都可操作，
    点关闭按钮、半透明背景或按 **Escape** 都可收起。抽屉只覆盖群聊主区，不盖左侧会话列表。
  - **抽屉跨断点**：窄屏打开抽屉后把窗口拉宽到 1280px 及以上，成员名单变成静态右列，
    背景与「成员」/「关闭」按钮自动隐藏，不会留下关不掉的浮层；再缩回窄屏时抽屉保持关闭
    （不会自行重开）。
  - **成员按钮只在群聊标签**出现：切到「成员视图」时头部没有「成员」按钮，抽屉同时收起，
    `aria-expanded` 不会谎报抽屉还开着。
  - 头部「反应链进行中…」会写出正在流式的成员名，所以抽屉关着也知道谁在反应。
  - 底部**原来**的「成员私有分栏」已经**删除**：底部分栏不再存在，私有过程改到
    「成员视图」里看，公开时间线拿回完整的垂直空间。
  - **滚动位置**：公开时间线、成员视图与成员名单三个区域各自记住滚动位置；切标签、
    开关抽屉再回来时回到原来的位置，不会被重置到顶部。
- **成员视图**：选择器列出全部成员（含已移除）。选中一个成员后显示：
  - **真实上下文与占用**：该成员最近一次真实发出的 `system` / `messages` / `tools`
    原始 JSON；有占用拆分时画占用环（分母是**该成员自己**的窗口），没有拆分数据时显式写
    「没有占用拆分数据：不渲染环」而不是画空环。快照有四种状态：加载中、正常、
    本次运行内没发过言、读取失败（**可重试**，不会伪装成「没发过言」）。
  - **私有过程（仅该成员可见）**：该成员在**本次已加载页**里的私有行；没有时写
    「本次已加载页里没有私有行」并提供「加载更早的消息」（与公开时间线共用同一游标）。
  - **未知作者**：不在成员表里的作者（脏数据）不静默丢行，成员视图用只读横幅
    「未知作者私有行」列出名字与行数。
  - 双标签切换只改本地状态：**不重拉 RPC**，输入草稿、时间线滚动位置与链状态都不丢。

**重载失败保留已加载内容**：群聊已经显示出来之后，如果一次自动重拉（例如点开关、消息事件
触发的重拉）失败，时间线、成员、分页游标与成员快照都**保留**，页面只多一条错误横幅，不会
把整页退回「正在加载群聊…」；重载失败会顺带清掉链状态与「正在反应」的显示，避免取消按钮
被已经结束的旧链误启用。只有**首屏第一次加载**失败时才会保留加载占位并显示错误。

**换群不重放旧链提示**：切到别的会话再切回一个群，上一条链的「已达轮数上限 / 被点名没有
回应」一次性提示**不会重放**；切回后这个群再跑完一条新链，提示照常出现（不承诺离开期间
结束的链在回来时补提示）。

## 气泡、头像与成员卡片

**头像从哪来**：模板上传了头像就显示那张图（图片经核心的附件接口换成 data URL 再渲染，
不暴露磁盘路径）；没上传、或图片文件丢了，就显示由**实体 id** 生成的身份图案 —— 成员用
成员 id、用户用用户资料里的种子。同一个 id 永远同一张图案，改名不换脸。头像取不到字节时
直接回落身份图案，不弹错、不阻断消息与群视图加载。

**状态点**：成员卡片名字旁的小圆点表示工作状态 —— 运行中是绿点并带脉冲（系统开了「减少
动态效果」时脉冲停下），空闲是灰点；运行中同时带可读的「正在反应…」文本（读屏可达），
不靠颜色单独表达。判定只认 `group.list` 的 `busy` / `runningMemberId` 与按成员归位的
`agent.streaming`；链在两个成员之间的间隙按空闲显示（不猜下一位是谁）。

**紧凑环**：成员卡片上那只小环是**只画环**的上下文占用（donut 描边环，中心空心），
没有图例、没有常驻数字。鼠标悬停或键盘聚焦到环上会浮出 **tokens 详情**：对话 / 窗口
tokens、二级摘要 / 一级摘要 / 原文三瓣的逐项数字，以及系统提示词与工具定义的固定开销。
三段都是 0 时仍然画一圈轨道环（不会留空白盒）；该成员本次运行内没发过言（没有快照）时
只显示「—」占位并标出状态，**不画空环冒充零占用**。web 的紧凑环不显示百分比（与旧版
成员视图里那只 `context-ring` 完整环是两种形态；完整环维持原样：旁置 tokens 与三瓣图例）。

**齿轮面板**：点成员卡片右侧的齿轮展开成员设置面板，里面装七件事 —— **模板**下拉、
**工具子集**（只能收紧）、**提示词追加**、**思考强度**、**生效结果**（生效工具清单与思考
模式 / 强度）、**保存**（重建实例）、**移除**。保存后**面板不自动收起**，可立刻在面板里
核对新的生效结果。在面板里换模板并保存会把模板名一起提交，成员的头像随之换成新模板的
头像（新模板没上传图就回到该成员的身份图案）。

**已移除成员**：卡片照常显示头像与名字（带「（已移除）」），齿轮仍可点开面板 —— 但面板是
**只读**的：模板、工具、提示词与强度控件禁用，保存与移除标为不可用且点击不发任何写请求；
面板里仍能看到它移除前的生效结果（历史成员的配置可核对，不会因为移除就无处可查）。

**同图靠名字**：同一模板上传了头像时，多个成员的头像会一样（属预期）。时间线里每条成员
消息上方都有名字、成员卡片上也有名字，所以**靠名字**就能归属；模板都没有上传图时两人的
身份图案本身就不同。

## 怎么操作

### 建组

点会话列表顶部的「＋ 组」。新组会立刻出现在列表里并选中。

组的共享工作区（也就是下面说的**群工作路径**）：`group.create` 可以带 `workspace` 指定一个
已存在的目录，不设就用产品既有缺省工作区（应用主目录）。成员创建时**继承**组当前的工作路径
（不给成员单独目录）。这个设置会**落库并持久化**（`sessions.workspace`）：**重启后工作区保留**
—— 核心重启后组上下文按保存下来的目录重建，成员继承同一目录；升级前创建、没设过工作路径的
旧组仍是缺省主目录，行为与以前一致。

### 群工作路径

位置：群聊标签**右侧栏的最上方**（成员名单之上；窄屏时在头部「成员」抽屉的顶部）。

- 显示该组当前的工作路径；没设过时显示「缺省（应用主目录）」。
- 长路径在栏里**单行截断**，鼠标悬停可以看全文（title 属性）。
- 点「切换」弹**文件夹选择框**（应用内的浏览框，不是系统对话框）：框里是当前目录的子文件夹，
  点文件夹进入下一层、点面包屑或「上级」回退，点「选择此目录」保存，点「取消」什么都不改。
  没设过工作路径时，框从**应用主目录**开始。框顶的**路径地址栏**始终显示当前文件夹，浏览后
  自动跟着变；也可以直接改路径后按 Enter 或点「跳转」（核心校验：合法就跳过去，输错在框内
  报错、不跳、地址栏回到当前文件夹）。点选仍是主用法，地址栏是给已知路径用的快捷入口。
  框高**固定**约视口七成（换文件夹不会跳高跳低），子文件夹很多时列表在框内滚动、框不会撑满屏幕。
  面包屑顶层是「此电脑」（Windows）：
  盘符根的「上级」回到「此电脑」，在那里可以换到其它盘（`C:` / `D:`…）；
  停在「此电脑」时「选择此目录」禁用（它不是真实目录）。
- 保存走核心的 `group.setWorkspace`：目录必须是**已存在的绝对目录**（框里点选或地址栏输入，
  核心都会校验）。成功后栏里立刻显示新路径，并**传播到该组所有在册成员的实例上下文**，下一次
  成员轮就在新目录里干活。
- 核心拒绝这个目录（例如没有访问权限、目录刚被删）时，错误显示在**框里**（含路径与原因），
  框保持打开，已保存路径的显示不变。
- **链运行中不能切**：「切换」按钮禁用并给出可读原因（悬停看），点了也不会发写请求；先取消
  反应链或等它结束。
- 这一栏**只装工作路径**，不是群公告：没有公告正文、编辑历史或未读标记。
- 没有「恢复缺省」按钮：把框导航到应用主目录再点「选择此目录」即可。
- 浏览器拿不到本机绝对路径的**系统**文件夹对话框（安全限制），所以这里是**应用内**的文件夹
  选择框，目录列表由核心的 `workspace.listDirs` 提供（只列子目录；Windows 的「此电脑」层
  列盘符；地址栏跳转也用它校验，不合法路径返回可归因错误）。这是实现事实，不是暂时没做。

### 删除群

会话列表里群行的「删除」先弹出确认浮层，确认后走 `group.delete`（核心负责停链、销毁成员
实例、级联删除成员 / 消息 / 摘要）；单聊行仍走 `session.delete`。删除当前会话后主区按
**下一条会话的类型**激活（删群后下一条是单聊就按单聊加载，反之亦然）；删到最后一条时
主区变成空聊天屏。

### 加成员

在群聊标签**右侧的成员名单**里填**显示名**、选模板、点「加入」（窄屏先点头部的「成员」
打开抽屉）。

- 显示名在组内必须唯一（只在**未移除**成员之间成立）；重名或空名会被拒绝并点名。
- 成员的 Agent 实例在加入时创建；回合结束**不会**销毁（它是持久实例，不是一次性子运行）。

### 编辑成员覆盖层

成员 = 模板 + 覆盖层。覆盖层只有三个字段（**空值三态**：字段缺席 / 显式 `[]` / 显式空串 三者互不等价）：

| 字段（代码里的名字） | 含义 | 空值语义 |
| --- | --- | --- |
| `toolsSubset` | 工具子集：只能在模板已有工具上**收紧** | 缺席 / 「null」 = 无覆盖；显式 `[]` = **零工具** |
| `systemPromptAppend` | 系统提示词**追加**（不替换模板提示词） | 缺席 = 不追加；空串 = 追加内容为空（不产生空行） |
| `thinkingEffort` | 思考强度（「low」/「medium」/「high」/「xhigh」/「max」） | 缺席 = 按模板推导；显式 `""` = **关闭思考** |

- 这三个字段**不是 `config.json` 键**：它们存在成员行（或单会话行）的 「overrides_json」 里，
  是「模板之上的那一层」，不改模板。
- 工具子集写模板没有的工具会被**拒绝并列名字**（不静默删）；模板后来删掉了子集里的工具时，
  生效集合会收紧并留一行日志（覆盖层存储本身不改写）。
- 保存覆盖层会**重建实例**：下一次发言就用新的工具清单与提示词。
- 思考强度是**下一消息生效**（沿用既有热更新口径），工具与提示词不逐轮热替换。

齿轮面板里的**生效结果**那一行（「生效工具：… · 思考：…」）就是这次解析出来的**生效配置**，
可用来核对覆盖层真的生效了（不是只改了界面）；它不再摊在卡面上。

### 自发反应（默认开）

组视图头部**第二行**有一个「**自发反应**」开关（`data-testid="reactions-toggle"`）。它存在
`sessions` 表的 `reactions_enabled` 列里（JSON 字段 `reactionsEnabled`）——**不是**
`config.json` 键，所以配置文档里找不到它。

**默认值有两副面孔，这是刻意的**：

- **新建的组默认开启**（点名不该是默认体验：用户说「甲讲笑话，乙评价」时，乙应该自己接话）；
- **从旧版本（schema v9）升级上来的既有组默认关闭**：升级不改旧体验，你可以在组视图里自己
  打开开关。

开启后，**每一条公开消息都会成为反应刺激**：

- 用户消息启动一轮；
- 同一轮里**后跑的成员**能在自己的视图里看到**先跑成员**刚发出的公开回复（串行可见），
  所以每条成员公开回复都被反应了 —— 但链的下一轮触发只取**该轮最后一条公开消息**的 `seq`，
  不会把轮内每条回复再各自排一轮；
- 成员的运行顺序是**加入顺序**（`created_at`）；本次用户文本里 `@显示名` 点名的成员排在
  第一个反应轮的最前面、且**必应**；
- **发送是异步的，而且永远接受**：点「发送」后消息先落库、链在后台跑，界面**立刻**回到
  可发送状态（不再一直显示「发送中」）。链运行中也能继续发：新消息照常写入，由每组一个
  内部执行器**吸收/排队**（同一时刻只有一条链在写原文，公开行不会交错）。链的进度、结束
  原因与每一步都从 `group.chain` 读，链进入终态时还会收到一条 `group.chain.completed`
  事件（本版本唯一新增的事件类型）。
- **每组上限**（反应轮数上限，默认 8，范围 1..50，界面可改）：只计**反应轮**，而且是
  **每条用户触发一份预算**——用户新发一条消息会把 `rounds` 重置为 0；agent 自己的公开
  回复不重置。正常聊天靠两条收敛防线自然停：① 一轮里没有任何新公开消息（全员沉默）⇒
  下一轮没有可反应成员 ⇒ 链自然停（`all_passed`）；② `last-reacted-seq`：成员只对
  `seq` 更新的公开消息反应，不对同一条反复接话。上限是防失控的保险：没有新用户消息、
  队列也空、预算耗尽时链以 `stopReason = round_cap` **优雅停止**（不是报错），后续点名 /
  定向发送照常可用。
  - 上限是**组设置**（`sessions.max_reaction_rounds` 列，JSON 字段 `maxRounds`），
    **不是** `config.json` 键；留空 = 用产品默认 8。
  - **定向轮不计数、不被拦截**：显式 `speaker` 的强制轮与安静态的 `@mention` 强制轮是
    用户点名，不是反应轮。

成员怎么沉默（**结构化 PASS**）：每个自愿反应轮与强制轮都会拿到一个 **`group_react`
终态工具**（`input_schema {pass: boolean, message: string}`），模型必须在本轮**恰好调用
一次**；正文不进入公开时间线，`message` 是**唯一**会公开的内容：

- `pass=true` ⇒ 沉默：不写公开行，时间线里看不到；`message` 写什么都被忽略（连「我这回合
  不发言」这类元话术也一起吞掉）。`pass=true` 不是失败，是群聊礼仪。
- `pass=false` ⇒ 公开发言：公开行**只写 `message`**（正文里的解释、`[PASS]` 之类都不会进
  时间线）。
- `pass=false` + 空 `message` ⇒ 不写公开行（自愿轮记 `empty`，被点名轮记 `forced_empty`）。
- **没有调用 `group_react` / 参数非法 / 同一轮多次调用** ⇒ 产品**先纠正重试**：像工具
  执行失败那样回一条纠正消息，要求模型重新调用（最多 2 次，按成员轮计）；重试合规就
  正常收尾。**超限仍不合规**才该步骤记 `failed`（错误码 `missing_group_react` /
  `invalid_group_react`），**不写公开行，也不回退到 `[PASS]` 文本匹配**；纠正过程与
  期间正文（含元话术）都不进时间线。

**普通轮不受影响**：单会话、关闭态纯 speaker（没开自发反应）等非反应轮**不注入**
`group_react`、不做 PASS 判定；在那些轮里 `[PASS]` 只是普通正文，照常进时间线。

**提示词怎么要求沉默**：开启态的自愿反应轮按「**默认沉默**」写——沉默是常态、发言是
例外；大多数轮应当返回 `pass=true`，只有一条非说不可、别人没说过的实质新信息才
`pass=false`。`pass=true` 不是失败，是群聊礼仪。提示词列了 4 个该沉默的样板（别人已
说过 / 纯表态无新依据 / 对话已收尾 / 与你的角色无关）与相关性门槛。**这是经验性的**：
模型仍可能话多，`round_cap` 是可靠兜底；"全 round_cap、零 all_passed"只说明该模型
偏话多，不是故障。

**被点名却仍不回应**（`pass=true`、或空 `message`）记 `forced_pass` / `forced_empty`：
产物里**不写公开行**、**不发 `turn.failed`**（它不是整轮失败）。它们只在 `group.chain`
的 `steps` 里可观察，web 在收到 `group.chain.completed` 事件后提示「被点名的成员没有
回应」。**这个提示不持久**：刷新页面后历史里没有它（没有对应的公开行）。

**取消**：链运行中顶部的「取消反应链」可用（核心说该组 `busy`，或 `group.chain` 为
`running`，或本页看到某成员正在流式 —— 三者任一成立）。它发 `agent.cancel {sessionId: 组 id}`，
停整条链并**清空排队**（已写入的用户消息保留，可重发）：

- 不带 `memberId`：停链 + 取消当前成员，回包 `cancelled: true` + `reactionChainStopped: true`；
- 带 `memberId` 且该成员**正在跑**：取消它并停链，`cancelled: true`；
- 带 `memberId` 且该成员在链里**排队未轮到**：停整条链，但 `cancelled: false`
  （它确实没在运行，不谎报）+ `reactionChainStopped: true`；
- 带 `memberId` 但该成员既不在链里也没在运行：可归因「当前没有在运行」，链继续跑。

`group.list` 的每个组项带 `busy`（布尔）与 `runningMemberId`（当前运行成员，成员间隙为
「null」）。**它们只是状态指示，不是发送拒绝条件**：`busy=true` 时照样可以 `group.send`，
新请求会入队/被吸收。**断线重连后**本地发送状态会丢，但重新拉 `group.list` /
`group.chain` 就能恢复「链在跑」的显示并让取消按钮可用。

### 发言人（可选）与点名

组视图**群聊标签底部**的「发言人」下拉：**开启自发反应时第一项是「（不点名，仅触发反应）」**，默认就选它
—— 只输入一条消息点「发送」，成员就会自己对这条消息反应。**发送是异步的**：点完「发送」
界面立刻回到可发送状态（链在后台跑），被点名成员的定向轮也在后台执行。选了某个成员则是**定向**：

| 开关 | 有没有 speaker | 有没有 `@显示名` | 行为 |
| --- | --- | --- | --- |
| 开 | 有 | 任意 | 该成员跑一轮**强制轮**（必应）；它产生公开回复 ⇒ 链从这条回复起；它 `pass=true`/空 `message` ⇒ 链从**用户消息**起（`@` 仍必应） |
| 开 | 无 | 任意 | 写用户消息一次 ⇒ 以它的 `seq` 起链（`@` 命中的成员在首轮强制） |
| 开 | 无 | 无 | 没有文本 ⇒ 可归因错误 `no_trigger`（不写任何行） |
| 关 | 有 | 无 | **旧普通轮逐字不变**：不注入 `group_react`、不做 PASS 判定，`[PASS]` 就是普通正文 |
| 关 | 有 | 有 | speaker 普通轮 + 按点名顺序的 mention 强制轮（两者都跑） |
| 关 | 无 | 有 | 组服务写用户消息一次 + 按点名顺序的 mention 强制轮（不起链） |
| 关 | 无 | 无 | 可归因错误 `no_speaker`（不写任何行） |

- **`@显示名` 只在用户消息里解析**：成员自己的公开回复里写 `@` 只是正文。匹配规则：取最长的
  成员名、名字后面必须是结尾 / 空白 / 标点；未命中的 `@…` 原样留在正文里（不报错、不删字）。
- **成员知道自己的名字（第一人称视角）**：身份锚告诉它「你就是「丙」本人；别人用「丙」
  称呼你（叫这个名字是在跟你说话，叫别的名字是在跟别人说话）；但你自己发言时用「我」
  ——「丙」只是别人叫你的方式，不要称自己为「丙」、不要在正文给自己署名，系统会自动把
  你的发言标为「丙」」；模板提示词里的自称/角色名不代表它在群里的身份。
- **每个成员每轮都看到当前群成员名单**：系统提示词会现读并注入「本群成员：甲、乙、丙。
  你是「丙」。」；成员增减**下一轮**就更新（不用重建成员、不用重启）；已移除成员不再出现
  在当前名单，但历史消息的归属仍保留。
- **不替其它成员发言**：每个成员的公开回复只代表它自己（第一人称）；它不会替别人发言、
  编造别人的观点，也不会抢答点名别人的问题，更不会在一条回复里模拟多个成员轮流说话。
  但它**可以**引用、回应、反驳别人实际说过的话——这是正常的群聊互动，也是实质贡献。
- **第一人称发言、系统自动署名**：成员的公开回复用「我」直接说内容，不会在正文开头写
  「丙：」「丙（作者本人）：」这类自己的名字/归属标签；时间线的署名由系统按作者自动
  显示，所以正文里看到的第一句就是它本人说的话，而不是旁白。
- **评价对象还没出现时先等待**：如果用户让人评价的东西（笑话、方案、正文）还没被发出来，
  成员会先沉默等待，不会凭空编一个对象或假装读过不存在的文件来评价；等对象作为新的公开
  消息出现后，后续轮再反应。即使用户点名了某个成员，对象没出现也先等待；强制轮会如实说
  「还没看到，请先给出」，不编造。
- **裸名点名（没有 `@`）也能工作**：例如发「丙讲个笑话，甲和乙评价一下」，丙凭身份锚
  判断叫的是自己，应当回应；甲、乙判断叫的是别人，除非有别人没说过的实质补充，否则
  保持沉默（`pass=true`）。这是提示词层面的经验性改善；**显式 `@丙` 仍走强制轮，更可靠**。
- **内部串行执行器**：同一个组同一时刻至多一个成员在写公开行（**整条反应链**也算一个
  运行单位），但这是内部调度细节——**发送永不因它在跑被拒绝**：新消息写入、请求入队，
  执行器在轮边界吸收它（更新触发、重置该用户触发的预算）。
- 不带文本、只点名一个成员时的两个前置门仍然有效（**关闭态纯点名**与**开启态强制轮**都适用）：
  - 该成员视图**为空**（什么可见项都没有）⇒ 拒绝，**不会发空 messages**；
  - 该成员视图最后一条可见项是**它自己的回复** ⇒ 拒绝（继续会退化成续写 / prefill）。
- 公开回复应当自包含（结论 + 文件指针）：其他成员看不到你的工具过程，只能按你写的路径去读。

**改名**：组的标题还是默认值（`新组` 或 `New Chat`）时，第一条用户消息会自动把它改成消息
前 30 个字符；**你已经命名过的组不会被改**。

## 出错时会看到什么

- **组会话没有自己的模板**：对组会话调用「切换模板」会被拒绝（每个成员的模板来自成员行）。
  会话列表底部的模板下拉在群聊打开时**禁用**，并显示「群聊模板由各成员决定」（要改模板请
  在成员名单里编辑对应成员的覆盖层）。
- **单 Agent 入口拒绝组会话**：`agent.send` 作用在组会话上会被拒绝并指明改用 `group.send`
  （`speaker` 可选）。这是防止组原文绕过投影被当成单会话历史喂给模型。
- **空视图 / prefill**：见上一节，两种都返回可归因错误（指明成员与原因）。
- **不存在的组或成员**：返回带对象 id 与原因的 JSON-RPC 错误。
- **没有发言者也没有 `@`**（关闭态）：返回 `no_speaker`；**没有文本也没有发言者**（开启态）：
  返回 `no_trigger`。两者都不写任何消息。
- **被点名成员不回应**：`group.chain` 的 `steps` 里会出现 `forced_pass` / `forced_empty`，
  界面在收到链结束事件后提示「被点名的成员没有回应」。刷新后该提示消失（它没有公开行，
  不是持久化告警），也不会发 `turn.failed` 事件。
- **链失败显示真因**：反应链进入 `failed` 时，主区顶部出现独立的「反应链失败：<真因>」提示
  （`group-chain-error`），真因来自 `group.chain` 的 `error` 字段（例如 provider 错误 /
  成员轮异常原因），不复用加载错误或视图错误的横幅。该提示是**一过性**的：下一次发送
  即清除；`completed` / `cancelled` 不显示旧错。
- **达到每组轮数上限**：链以 `completed` + `stopReason = round_cap` 停止（不是报错），
  界面提示「已达轮数上限」；后续点名 / 定向发送照常可用，也可以把该组的上限调大。
- **组内没有成员在运行**时点「取消反应链」：返回「该组当前没有成员在运行」（真话）；带
  `memberId` 且该成员不在运行时会指名它。
- **链运行中改组设置**：`group.update` 返回可归因 busy（不排队），设置值不变。
- **群工作路径保存失败**：核心拒绝所选目录（没有访问权限 / 目录刚被删等）时，文件夹选择框里
  就地显示错误（含路径与原因），框不关、已保存路径不变；链运行中「切换」按钮本身是禁用的。
- **重启后组工作目录已被删**：核心会以可归因的 `workspace_unavailable` 拒绝建成员 / 跑成员轮
  （消息里点名该路径），不会偷偷用主目录或空工作区顶替；把工作路径切到一个存在的目录即可恢复。

## RPC 一览（无头核心）

| 方法 | 参数 | 说明 |
| --- | --- | --- |
| `group.create` | `title?` / `workspace?` / `reactionsEnabled?` / `maxRounds?` | 建组并建立组上下文；给了 `workspace` 时**先校验再落库**（重启后保留，见「群工作路径」），省略 / 只有空白 = 视为未设置（用缺省主目录）；`reactionsEnabled` 省略 = 新建组**开启**自发反应；`maxRounds` 省略 / 显式 null = 产品默认（8），范围 1..50，越界 `-32602` |
| `group.setWorkspace` | `groupId` / `workspace` | 切换组的共享工作路径：校验（绝对 / 存在 / 是目录）→ 组上下文生效 → 落库（核对恰好一行）→ **传播到所有在册成员实例** → 返回 `{group}`（含 `workspace`）。非法路径 / 单聊 id ⇒ `-32602`；反应链或任一成员运行中 ⇒ 可归因 busy（不排队、不改值） |
| `group.update` | `groupId` / `reactionsEnabled?` / `maxRounds?` | 改组的运行设置（至少给一个字段）；`maxRounds` 显式「null」 = 恢复默认（与**字段缺席**不同：缺席 = 不改）；缺字段 / 类型不对 / 越界 ⇒ `-32602`；链运行中 ⇒ 可归因 busy |
| `group.chain` | `groupId` | 当前 / 最近一条链的只读状态：`groupId` / `sessionId` / `status` / `triggerSeq` / `rounds` / `stopReason` / `error` / `steps`。`status ∈ {idle, running, completed, cancelled, failed}`；`stopReason ∈ {all_passed, round_cap, cancelled, failed, no_members}`（运行中为 null）；`error` 为字符串或 null（`failed` 时非空且含可归因文本，`completed` / `cancelled` 为 null）；核心重启后为 `idle` |
| `group.list` | — | 全部组 + 每组成员清单（id / 显示名 / 模板 / `removedAt` / 「overrides」 / 「effective」）；组项另带 `reactionsEnabled`、`maxRounds`、`busy`（布尔）、`runningMemberId` 与 `workspace`（组的工作路径设置值，字符串或 null） |
| `group.delete` | `groupId` | 删组：成员 / 消息 / 摘要随外键级联删除（先停反应链、再取消并销毁成员实例） |
| `group.member.add` | `groupId` / 「name」 / `templateName` / `overrides?` | 加成员（重名或空名可归因拒绝） |
| `group.member.remove` | `groupId` / `memberId` | **软删**成员（行与历史保留，同名重建是新 id）；先停反应链 |
| `group.member.update` | `groupId` / `memberId` / `name?` / `templateName?` / `overrides?` / `clearOverrides?` | 原地改成员（id 不变）并重建实例；先停反应链 |
| `group.send` | `groupId` / `speaker?` / `text?` | **异步且永不 busy**：`speaker` 可选（省略 = 开启态纯触发 / 关闭态按 `@mention` 定向）；写完用户消息（若有文本）与标题后**立刻**回 `{status: started, triggerSeq}`；链运行中再发也接受（入队/被吸收），**不会**回 `busy`。结果**不带** `steps` / `rounds` / `finalText` / `memberId` |
| `group.view` | `groupId` / `memberId` | 该成员**本次运行内**最近一次真实发出的上下文快照（**反应轮也算**）；没发过 ⇒ 「null」 |

`group.chain` 的 `steps` 每条是一个可观察的步骤（**不是第二套消息存储**）：

- `source ∈ { speaker, mention, reaction }`；
- `status ∈ { replied, passed, forced_pass, forced_empty, empty, failed, cancelled }`；
- 另有 `memberId` / `triggerSeq` / `publicSeq` / `finalText` / `error`。

链进入终态时，客户端还会收到一条 `group.chain.completed` 事件（`agent.event`，payload
带 `groupId` / `sessionId` / `status` / `stopReason` / `rounds` / `triggerSeq`；**steps 不进
事件**，需要时查 `group.chain`）。

相关的既有方法：

| 方法 | 群聊上的行为 |
| --- | --- |
| `session.list` | 每项带 「kind」（「single」 / 「group」）、`reactionsEnabled`、`maxRounds`（整数或 null）、`workspace`（工作路径设置值，字符串或 null）与 「overrides」（会话级覆盖层，可空） |
| `message.query` | 每条消息带 `author`（稳定成员 id，用户消息为 「null」）与 `visibility`（`public` / `private-to-author`）；分页语义不变 |
| `agent.event` | 成员运行产生的组事件在 `sessionId` 之外带 `groupId` 与 `memberId`；**组服务自己写入的用户消息只带 `groupId`**（没有成员可归，不伪造 memberId）；链进入终态时发 `group.chain.completed`（本 change 唯一新增的事件类型）；`forced_pass` / `forced_empty` **不走** `turn.failed` |
| `agent.cancel` | 组会话按组路由：链运行中停整条链并**清空排队**，回包带 `reactionChainStopped`；带 `memberId` 取消排队成员 ⇒ `cancelled: false` + `reactionChainStopped: true`（不谎报 cancelled）；没有链时「该组当前没有成员在运行」 |

**`reactions_enabled` 与 `max_reaction_rounds` 不是 `config.json` 键**：它们是 `sessions`
表的列（组级持久属性），`configuration.md` 里没有它们，也不该有。

## 已知限制

- **看不到他人私有过程**：成员之间只看得到彼此的公开回复；思考与工具过程只属于作者自己。
- **成员看不到彼此的工具证据**：协作靠共享工作区里的文件 + 公开回复里的文件指针。
- **关闭自发反应后仍只支持点名**：关闭态没有轮转、主持人、自由抢话；一次点名一个成员。
- **无并行**：反应链里的成员是**串行**跑的（并行反应留到以后）；链越长越慢。
- **每组上限（默认 8，范围 1..50，界面可改）**：反应轮数上限只计反应轮，达上限以
  `stopReason = round_cap` 优雅停（不是报错）；定向轮不计数、不被拦截。它是组设置
  （`sessions.max_reaction_rounds`），**不是** `config.json` 键。链没有别的深度上限配置项。
- **链状态只在内存**：`group.chain` 是「本次运行内」的当前 / 最近一条链，核心重启后为
  `idle`；重启后看不到旧链的 `steps`（消息与公开行不受影响）。
- **无 token 预算治理**：N 个成员 × 多轮 × 每次生成都会烧 token，本期没有预算护栏；
  上限只管轮数，不管每轮 token。
- **沉默率是经验性的**：提示词按「默认沉默 + 4 个 pass=true 样板」写，但是否真的沉默取决于
  模型；`group_react {pass:true}` 是模型主动选择，产品**不保证**大多数轮一定沉默。
  `round_cap` 仍是可靠兜底（达到上限就优雅停），"全 `round_cap`、零 `all_passed`"只说明
  该模型偏话多，不是故障。
- **`forced_pass` 提示不持久**：被点名成员不回应的提示只在这次发送后显示；刷新页面就没了
  （它没有对应的公开行）。
- **重启后真实上下文视图为空**：`group.view` 只给**本次运行内**真实发出过的快照，重启后是空
  （界面显示占位）。这是既定语义，不会用历史拼一份"没发过的上下文"。
- **已移除成员只读**：已移除成员仍有成员视图里的历史私有行（只读），但不能再被点名发言；
  同名重建是新身份，看不到旧成员的私有行。
- **旧组升级后默认关闭**：从旧版本升级上来的组是安静态（点名体验不变），要在组视图里自己
  打开「自发反应」。
- **Flutter 只有占位**：组会话在 Flutter 会话列表里可见，点开显示「请在 web 组视图打开」，
  不加载整份原文、也不进入单 Agent 对话界面。
- **公开回复不带附件**：组成员的最终公开行只存正文（「tool_calls」 与 「thinking_json」 均为
  NULL），v1 公开回复不带图片附件。
- **摘要各自一份**：同一段公开内容会被各成员视图各压一遍（N 份摘要算力与存储），这是
  "摘要 = 各成员的主观记忆、原文才是唯一真相"的代价。
- **头像文件丢失不报错**：模板 / 用户的头像文件被删或移走时，界面直接回落身份图案（装饰性
  资源，不弹错误横幅、不阻断渲染）。
- **同模板同上传图时头像相同**：多个成员共用同一个有上传头像的模板时头像会一样，靠名字
  区分；产品不做成员级头像角标。
- **紧凑环不给百分比**：成员卡片上的紧凑环只画环、悬停 / 聚焦看 tokens 详情；这一形态不
  显示百分比（web 的完整环也维持现状：tokens 与三瓣图例）。
