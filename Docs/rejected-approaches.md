# 已否决 / 已失败的方案台账

**这份文件是什么**：**唯一**的「试过并且失败的方案」台账。目的只有一个 —— **防止我或 Workflow 子 agent 把已经证伪的旧方案重新翻出来当新解法**。

**性质与纪律**（违反即失效）：

- **只追加，不重写**；每条**不超过 3 行**，用表格，**禁止写过程叙述**。
- **禁止行号引用**（文件一编辑就失效）—— 用函数名 / 变量名 / 唯一字符串 / 日志原文。
- **不作为审查对象**：不要开审查去挑这份文件的措辞（那是"审描述"，必然不收敛）。
- **只记"真的试过并失败"或"提出后被实测否决"的方案**；没试过的猜测不入账。
- **每条必须写【何时可以重新考虑】** —— 否则台账会退化成对好想法的永久封杀（锚定）。
- **举证责任在提出方**：任何新方案若与台账某条**实质相同**，必须给出"**这次哪里不同**"的可核证据；给不出 → **该方案作废，不得实施、不得上报为发现**。

**怎么用**：①我提方案前先查这里；②作为 Workflow 审查的**第三份输入清单**；③当某一轮发现"**上一轮修复自己引入的问题**"、或某组数字被撤回时，**当场补一条**进账。
